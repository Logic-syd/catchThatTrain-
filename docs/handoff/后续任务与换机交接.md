## 2. 新电脑恢复步骤

安装 Git 和 Node.js 20 或更高版本，然后：

```sh
git clone -b codex/bugfix-mobile-flow-events https://github.com/Logic-syd/catchThatTrain-.git
cd catchThatTrain-
git status --short --branch
npm ci
npm test
npm run build
npm run dev
```

浏览器打开终端实际打印的地址，默认通常是 http://localhost:5173/。如果端口被占用，先确认服务地址，不要把另一个目录的旧页面误当成新代码。换电脑后需要重新启动开发服务，旧电脑的 localhost 链接不会变成远程测试环境。

需要提交或推送时，在新电脑重新配置自己的 Git 身份和 GitHub 授权。项目代码、素材、锁文件、文档、正式测试和数值报告都在仓库里；不需要从旧电脑复制 `node_modules` 或 `dist`。

### 哪些东西不随仓库搬走

- GitHub 保存仓库文件，不保存完整聊天记录。不能仅凭代码已上传，就认定新设备一定能看到这段聊天；本文和另一份总结已经保存继续工作所需的主要上下文。
- 游戏战绩、成就、人物解锁在浏览器本地存储。项目目前没有账号云存档，换设备不会自动继承；不要把新设备从大学生开始误判成“失败回锁”的同一个 bug。
- 正式站点、`/test/` 和本地环境的存储有区别；测试站用 `playtest:` 前缀。`localhost` 与 `127.0.0.1` 也是不同来源，不应交替使用来验证进度持久性。
- 旧的 `artifacts/` 目录含临时回归脚本和截图，没有上传；正式可复现的测试在 `src/*.test.*`，数值脚本在 `scripts/`。旧截图不应作为当前版本的验收结果。
- 旧电脑上的 Downloads 原始路径和聊天附件临时路径不会随 Git 克隆。用户提供的设计 Markdown 已归档到 `docs/design/`；继续工作应使用仓库副本。
- 本地开发进程、GitHub 登录授权、应用设置不属于项目仓库。

## 3. 已完成的数值工作，不要重做成旧方案

1. 时间账本按实际倒计时对账，地铁、排队、睡觉、安检不应重复扣时。
2. 开局采用“正常地铁行程＋站内赶路＋必要操作＋预计环境处理＋人物容错”。四人物容错为 **240／180／135／90 秒**，按大学生、打工人、游客、家长排列；统一角色方向罚时倍率已移除。
3. 冲刺已经降速并限制持续收益。大学生短冲峰值 1.5 倍，冲刺负荷超过 3 秒后逐渐掉速，到 7 仍按现有规则岔气；打工人 1.4、游客 1.3、家长 1.25 倍。不要为了平衡选项再次一起乱改冲刺。
4. 普通读题／操作只自然消耗时间，不因局部提示倒数结束再罚一笔，也不会自动选答案或完成设施。游客闹钟、没听清报站仍保留有实际后果的限时窗口。
5. 整理身份证 10 秒，大学生／打工人吃饭各 20 秒，咖啡 20 秒，短休息 8 秒，调整轮子 6 秒。饥饿影响实际赶路，蛋糕继续占手、负重和消耗体力。
6. 最新正常基线已重测，配置在 `src/referenceBudgets.ts`，数据来源是 `docs/design/preparation-reference-report.json`；不要把早期 `sprint-reference-report.json` 当作当前冻结基线。

具体参数和新开局表见 [准备收益与读题计时修正 V1](../design/我一定会赶上这趟车_准备收益与读题计时修正_V1.md)。测试成功数是声明策略下的结果，不是真人首局通过率。

## 4. 接下来要做什么

以下按建议顺序排列。它是交接清单，不代表用户已经批准自动发布所有后续工作。

### P0：先确认修复版的实际手感

先在新电脑恢复开发环境，让用户用手机或手机尺寸试玩最新分支。需要远程发给朋友时，按第 6 节部署测试环境，并在成功后核验链接。

验收重点：

- 准备的时间代价与后续收益能否感受到；吃与不吃、喝与不喝是否会根据处境改变选择，而非固定选第一个。
- 普通任务慢读不再突然额外扣几十秒，选完仍需做真实操作；错过闹钟、车门等真正的错过仍有后果。
- 地图移动、小人疲惫／奔跑、阻挡中的动作和放行反馈是否连续。玩家应知道自己当前能做什么，不是在看自动播放。
- 手机操作区固定底部，当前所需按钮同时够大且可达；不能为了完成一次操作上下滚动找按钮，可以遮挡部分地图。
- 各站方向线索是否提前给清楚，外地玩家是否也能解题；大学生不应混入打工人的工作群剧情。
- 解锁回归：大学生赢一次 → 打工人解锁 → 后续失败 → 刷新／重新打开同来源 → 仍然解锁。不能仅验证当局内状态。

这些体验有实现和测试基础，但最新这批数值尚未完成真实玩家验收。不要因脚本通过就标记手机体验全部完成。

### P1：完成剩余的选项、资源和路线分析

在现有分析脚本上补场景，不从头另造一套计时器：

| 未完成事项 | 具体做法 | 验收依据 |
| --- | --- | --- |
| 更丰富的资源状态 | 测低体力、低专注、重负重、蛋糕占手、游客疲劳及家长孩子状态 | 至少能解释哪些情况下准备划算、哪些情况下先走划算 |
| 情感／剧情选择定位 | 蛋糕、妈妈特产、纪念品不必强行等价为速度奖励；确认其情绪、称号或后续事件价值 | 不能声称所有选项已平衡；工资真话／报低的数值优势仍需讨论，保留用户已定剧情 |
| 广州中央路线 | 之前的参考场景中，家长走中央比外围慢约 85 秒，接近整份容错 | 重新测当前版本；结合换层、拥挤、体力与信息线索判断是否值得调整 |
| 上海近路／外侧 | 之前稳定处理障碍的脚本普遍走商店近路更快 | 加入真实操作误差、拥堵与资源状态，检验外侧“更稳”的价值 |
| 真实错误次数 | 目前部分站点请求 3 次方向错误，脚本实际只产生 1 次 | 报告实际错误数；加入不同位置、不同类型错误，不能用请求次数冒充执行次数 |
| 家长慢读容错 | 最新每题读 8 秒的上海家长为 6／8，其余 23 组为 8／8 | 拆分自然阅读、环境和操作损失，不能直接加大开局来遮住原因 |

### P1：拆清环境损失，再实现预算约束

原始数值稿的“不可控环境平均约 35 秒、单局上限 75 秒”**尚未完整实现成硬约束**。现有账目是参考玩家遇到环境后的处理成本，其中还混有主动应对，不等于纯随机损失。

下一步先分清：设施正常服务时间、不可避免等待、主动绕路、玩家操作失败。然后让新随机事件在触发前遵守累计预算。不要把已扣时间事后返还，也不要把平均环境时间算进开局后，再额外加一份 35 秒。

### P2：混合行为与真人首次通关率

- 大学生首次通关约 75% 是用户提出的目标，目前未被真人样本证明。早期只有约 3–5 位朋友，大多一直冲刺且剩 500 秒，不足以拟合通过率。
- 扩展到熟练、普通、乱玩等明确行为模型；不能让模拟玩家偷看隐藏最优答案，也不能反过来调脚本失误概率伪造目标通过率。
- 分开随机种子来源：环境、行为、展示顺序，避免选一个答案改变所有后续随机结果，导致配对比较难解释。
- 记录人物、车站、首次／重玩、版本提交、读题与关键操作、剩余时间、失败原因和玩家反馈。先用人工试玩记录即可，不默认接入第三方遥测服务。
- 检查至少 12 次有效操作，但不把连续点击或重复按键凑成任务数。保持地图赶路节奏，避免为凑数量塞连续弹窗。

### P2：继续完善地图交互

现有地图已经有真实拦停和绕行；还没有完整的多人自主移动、互相避让、电梯上下客模拟。优先打磨短而清楚的互动：堵门、扶梯出口停步、横穿小孩、慢安检、关闭人工窗口。每次都应看得见阻碍，操作能改变局面，通过后能继续原目的地。

继续检查 A/B/C 队伍是否同步变化、轮到自己后的放包／取包／放行是否清楚，以及被小孩打断时醒目的扣时反馈。历史上这些点被多次指出，不能因布局或系统重构而退回静态页面。

### 后置事项

出行家庭／婴儿车家庭仍是后续人物规划，原稿已收录，不等于已可玩。国内更方便访问的托管与发布渠道曾讨论，但没有确定新平台。先稳住当前体验和测试流程，不在本轮擅自增加平台、账号或商业化。

## 6. 分支、测试环境和发布约定

继续在当前修复分支工作。不要每改一句文案就开新 beta、改版本或合并 main。用户已经分享过旧链接，开发、测试和正式发布必须区分。

- 正式入口：https://logic-syd.github.io/catchThatTrain-/
- 测试入口：https://logic-syd.github.io/catchThatTrain-/test/
- 推送修复分支本身只做 PR 检查，不等于部署。
- 需要给朋友验收时，推送后手动运行现有工作流：

```sh
gh workflow run pages.yml --ref codex/bugfix-mobile-flow-events
```

等待工作流成功，检查 `/test/build.json` 的提交与目标分支一致、入口和静态资源可加载，再发送链接。曾出现过测试入口 404，不要在部署未完成时说“已经可以玩”。本次交接没有重新检查线上当前部署提交，因此不能把最新 Git 提交直接称作线上版本。

现有工作流会保留 main 正式站点并生成 `/test/`；main 更新会部署正式站点，可能覆盖先前测试目录，必要时再部署测试分支。正式发布应在明确的验收节点通过 PR 合并，再按既定流程打 tag。
