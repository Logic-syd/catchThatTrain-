# 大学生虹桥操作模板 V1

日期：2026-10-13。范围：大学生 × 上海虹桥 × 普通／极限，作为后续人物和车站改造的首个样板。本文记录本轮操作设计、时间资源约束和交付证据；“设计目标”不自动等于已经验收，实际覆盖与验证见文末。

用户要求：路上的障碍、选择电梯和检票口都要有操作，避免把连续赶路拆成简单选择题。大学生首关要让玩家看见自己的观察、避障与冲刺成果，六站合理新手平均成功率目标仍为85%–90%，普通与极限分别报告。该目标不要求虹桥单站也落在85%–90%，更不要求每次胜利都卡在最后几秒。

本模板与[任务成本与收益规则](./任务成本与收益规则_V1.md)、[准备收益与任务资源规则](./准备收益与任务资源规则_V1.md)、[等待状态与操作规则](./等待状态与操作规则_V1.md)、[人物难点与事件规则](./人物难点与事件规则_V2.md)、[难度区间与首关体验](./难度区间与首关体验_V3.md)共同使用。原始设计稿保留。

## 1. 样板要让玩家反复完成的事

**看到情况 → 决定路径或时机 → 操作人物通过 → 看见真实结果。**

- 路障提前进入视野，玩家左右换道、分段冲刺；碰上后看见阻挡并换到空道。
- 路口呈现能走进去的入口、队伍和指示牌。玩家操纵人物抵达所选入口，抵达才提交该入口的正式选择。
- 路边诱惑能直接路过。只有玩家主动停留，才进入摸猫、围观、扶人或买饮料的处理与费用。
- 必须处理的事继续保留与物件对应的操作：滑开挂住的背包、找到证件、完成换层、刷证、登车。
- 完成任务后恢复普通步行，保留主动休息、阻挡、失焦停止和冲刺必须重新输入的边界。

“有操作”不等于把每个按钮都换成连点。换层要权衡体力，长廊要权衡路程与障碍，队伍要看通行情况，大厅要读标识。简单且可预判的输入承接这些判断。

## 2. 从准备到上车的完整流程

下表列出模板的操作安排。准备、地铁和已有实物操作承接现行规则；局部场景与路边诱惑按文末实际覆盖验收，不能仅凭本表视为全部已完成。

| 阶段／稳定任务 ID | 玩家看见什么 | 怎么操作 | 有意义的取舍与反馈 | 时间、资源与后续消费者 |
| --- | --- | --- | --- | --- |
| 出门准备：`tea`、`id`、`breakfast` | 奶茶、证件、早餐的当前实际效果 | 保留三项出门安排，不把这次改造扩大成新的准备小游戏 | 奶茶占手但有现行能力效果；查证件缩短后续查找；早餐避免候车厅饥饿 | 固定45／10／25游戏秒，跳过0；另计实际思考与输入时间。容量、持杯、证件位置、饱腹按现行消费者结算 |
| 地铁路线与方向 | 当前起点、线路、换乘、方向与预计余量 | 选实际路线，注意站点，在正确车站下车；保留已有到站操作 | 时间成本包括步行与换乘；提前找证件有后续用途，错方向／错站有真实后果 | `ROUTE`锁定行程费用；车内并行动作不重复收取同段行程；到站操作实际计时 |
| 出站连续赶路 | 三条道路、前方行李／人群、冲刺负荷 | 左右换道、按住冲刺、松手步行；需要时主动休息 | 看准空道可连续通过，松手能控制冲刺负荷；实时显示真实避障次数与冲刺估算收益 | 移动与倒计时走同一小步；耗能、恢复、碰撞和位移沿用现行规则 |
| 随机实物阻挡：`bag-snag`、`elder-block` 等 | 挂住的肩带、路中阻挡与可通过的空隙 | 保留已有滑动解障等实际操作；未迁移的随机事件须明确列为保留项 | 障碍解除后才能继续；不靠只播动画就假装已处理 | 现行固定成本、实际操作时间各计一次；不另造奖励 |
| 路边小猫：`student-cat` | 路旁小猫和可主动停留的提示 | 继续前进即路过；主动停下后才处理 | 幸福感是真实剧情记录，赶车受停留影响 | 接受后固定30游戏秒，幸福感实际最多+20；拒绝无固定费。等待自然恢复仍按共用规则 |
| 上出发层：`vertical-choice` | 扶梯、楼梯、直达电梯的真实入口及路线提示 | 在局部场景中引导人物走进入口 | 体力充足可以选楼梯；电梯等待换恢复；扶梯还要面对通行状态 | 到达才提交现行选项；楼梯22体力在完成操作时扣，电梯35秒等待一次结算；扶梯路线进入后续扶梯任务 |
| 三部扶梯：`escalator-choice`、`escalator-ride` | 三处入口、入口周围障碍，以及本局各扶梯的畅通／正常站立／拥堵情况 | 操纵人物到选中的入口，再完成当前扶梯操作 | 提前看见人群状态再选路线；显示读取本局真实状态，进入口时不重新抽取拥堵结果 | 畅通快走保留实际点击；站稳10、正常15、拥堵30等待游戏秒沿用现行规则，操作另计。楼梯／电梯分支跳过选扶梯，不重复乘坐 |
| 路边围观：`student-spectacle` | 扶梯之后的热闹人群 | 能路过，也能主动停留围观 | 不打断“选扶梯→完成扶梯”的操作链 | 接受后固定40游戏秒，幸福感实际最多+20；活动为等待 |
| 长廊分流：`sh-corridor` | 商店通道与外侧长廊，入口宽窄和人群可见 | 在局部场景中绕过障碍，走入所选通路 | 商店更短、人群密；外侧更长、障碍少。选对适合自己的路线能在后续赶路兑现 | 同一后续路段分别乘0.75／1.1，障碍密度分别3／1；读取正式 `stationDecision`，不把缩短路程又额外折成赠送秒数 |
| 安检排队：`security-queue` | 三支队伍及可观察的行李、人数和通行情况 | 观察后操纵人物走到队尾入口 | 人数少未必处理快；处理速度信息必须与实际队伍成本对应 | 学生队列现行费用24／55／32秒，布局由本局状态决定；排队部分按统一等待恢复，不重复叠旧队伍恢复 |
| 路边扶奶奶：`student-help-grandma` | 安检队列之后需要帮助的人 | 直接路过，或主动停留扶她到电梯再回来 | 道德积分与赶车时间形成取舍；不和随机拦路老人混为同一任务 | 接受后固定35游戏秒额外步行，道德实际最多+20；不能将这35秒当站立休息 |
| 随机安检处理：`security` | 背包中需要交出的物品 | 在图中找到并点出目标物品 | 正确处理才放行，不用新增选择题确认已经完成的动作 | 沿用当前实际输入与固定20游戏秒处理费用 |
| 候车大厅：`station-sign` | 车票上的目标与头顶“1–15／16–30”方向牌 | 读牌，操纵人物进入对应方向的通路 | 答案来自车票和路牌的匹配；入口不额外标“正确选项” | 正确无固定折返费，走错按现行55游戏秒；已经看过地图的知识仍可复用 |
| 路边奶茶：`student-tea-shop` | 不用排队的茶颜悦色 | 能路过，也能主动停下来买 | 幸福感诱惑，不追加准备奶茶的敏捷、容量或恢复增益 | 接受后固定25游戏秒，幸福感实际最多+20；活动为等待 |
| 取证件：`identity-search` | 书包夹层与已知位置提示 | 找到并取出真实证件；准备检查过则利用已记住的位置 | 前期准备在这一刻减少查找负担；已经提前找好就跳过 | 查找实际操作与当前规则一致，错误翻找仍记录；不按准备旗标虚记节省秒数 |
| 目标检票口下的八通道：`gates` | 当前目标编号、八条通道的排队与靠近距离 | 操纵人物绕过挡路物，走入所选通道 | 排队与距离一起判断，远处空通道可能更快；每局队列位置不能靠固定序号猜最优 | 同一目标检票口的8条通道，**不是8个不同检票口**。正式 `fixedWalkSeconds + waitSeconds` 只收费一次 |
| 刷身份证：`gate-scan` | 当前通道读卡区和绿灯 | 按住刷证，完成后放行 | 接近检票口不算检票成功，必须完成读卡 | 沿用1.2秒所需操作及持杯修正、实际计时、截止判断；完成才置 `gatePassed` |
| 最后一段与登车：`board-train` | 车门、剩余距离与当前体力 | 继续避障与控制冲刺，最后完成现有三次登车点击 | 前面的体力管理给最后一段留下选择，成功以真实上车为准 | 检票后倒计时含义切到发车；登车所需输入与现行截止规则不跳过 |

## 3. 连续赶路和关键地点的节奏

6–8个“必须处理的关键地点组”是后续试玩时检验节奏的方向，不是本轮无条件保证的任务数。换层包含选路线、靠近扶梯、完成换层；安检包含排队和可能的实物检查；检票包含选通道和刷证。同一个地点组可以有多个底层任务 ID。

四个路边诱惑离开“无论接受与否都强制停步”的队列。它们仍属于完整旅程，显示时机、可接近窗口和已处理状态必须可追踪；路过之后不在下一个路段再次收费。当前样板在对应路段显示可点击热点，脚下继续前进；点击先停步并解除冲刺，按住完成当前小动作才接受正式费用与剧情积分。也可以“收手，继续赶车”，只留下实际已经发生的停步时间。处理后回到原处，剩余路段仍需自己走，不能借互动跳过路程。

暂时不删除背包、随机老人、安检物品、行李箱、极限旧票等既有事件。它们会改变本局任务数量与停步次数，必须用实际日志分别统计“地点组、事件、按键／手势、被动等待”，不能把一个入口的移动帧数当成几十次玩家交互。

## 4. 可复用局部场景的合同

### 场景内容与输入

每个场景至少提供：稳定事件 ID、可进入区域、人物起点、入口矩形／到达区、可见阻挡、入口公开信息、正式选项映射，以及触屏和键盘说明。

触屏可按住目标方向或拖动引导人物；键盘可持续移动。松手、指针取消、失焦、切换场景均清除持续输入。人物必须逐步走到入口，不能把一次点击入口等价为直接提交答案。场景内可见阻挡应真正挡住直线路径，并留有可绕过的路径。

入口只能映射当前事件提供的正式选项，不能自行复制价格、等待比例或属性效果。进入一次后锁定完成状态，旧场景的输入、旧入口索引和重复到达不得继续结算。路边活动以所在 `stationBeat` 作为 `revision`；前一道热点留下的延迟 `indulge` 提交不能接受下一道热点，即使两者选项 ID 相同。读题期间资源变化后，使用提交时的标准效果与边界。

### 信息必须支持判断

- 换层入口写用途与能观察到的状态；楼梯、电梯的真实取舍要能在进入前获知。
- 长廊入口的人流和路程提示来自正式路线参数。
- 安检的行李与人数映射到本局队列，观察得到的信息必须有消费者；纯装饰动画不能冒充实时队伍模型。
- 大厅保留车票与方向牌，由玩家匹配数字。
- 检票八通道保留当前排队和附加步行的公开成本，不能依赖隐藏正确索引。
- 本样板在三扶梯场景提前公开同一 `stationLuck` 的畅通、正常站立与拥堵状态，费用预览通过正式效果生成；选中后仍需完成扶梯操作。不得重新抽取结果，也不得沿用旧卡片“看不清情况”的说明来描述新场景。

### 时间与资源只走一条账

局部场景是处理当前事件的真实操作，其经过时间读取主循环推进的 `eventElapsed`，沿用每真实秒推进1游戏秒。位置绘制和输入可以逐帧更新，但不能拥有另一只扣时、回血或补时的钟。主计时停止推进时，局部人物也不能凭独立计时器无限移动到终点。

正式选项费用继续按当前 `seconds`、`waitSeconds`、`fixedWalkSeconds` 分类：局部入口操作时间与之后的路线／等待费用分别说明、分别记录一次。尤其是检票通道，场景靠近是选择入口的实际操作，正式附加步行是进入后的通道支路；不要把同一段视觉距离同时宣称为两份真实路程。

局部移动不能新增普通旅程位移、跑道避障次数、冲刺收益、储备消耗或剧情奖励。等待恢复保留现行规则及上限，费用提交也不能再把已经发生的 `eventElapsed` 扣一遍。预测通过 `spatialOperationSeconds` 使用同一场景几何、绕行路径与移动函数，估计到入口边界的操作秒数，另加2秒阅读与正式选项费用；当前事件扣除已经发生的 `eventElapsed`，仍是估计而非实际人物轨迹回放。预测不直接扣时，不再默认新场景只需一次瞬时点选。

### 安全恢复普通步行

完成任务只能在本局允许继续行走时恢复普通步行。当前事件未解除、碰撞仍挡路、游戏结束、主动休息或窗口失焦都不能被自动恢复覆盖。恢复步行不继承之前按住的冲刺，也不跳过当前路段剩余距离。任务结束后马上出现另一强制事件时应保持停止。

本样板允许站内处理事件时查看地图和车票。打开信息面板属于主动停步，解除持续输入，时间仍以1倍流逝；当前事件保留。关闭面板后重新进入当前操作场景，从场景起点重新操作，原路段与已经发生的耗时不回滚。完成该事件后仍保持主动停步，需要重新点“开始前进”。这避免关掉地图时突然自己跑起来，也明确当前版本不会跨信息面板保存局部人物坐标。

## 5. 后续人物／车站如何复用

| 可复用部分 | 新关卡提供的参数 | 不能靠换皮省掉的工作 |
| --- | --- | --- |
| 连续道路 | 路段长度、障碍预告、位置、密度、角色速度与冲刺限制 | 确认可提前看见、存在可行空道，实际碰撞和资源影响有证据 |
| 局部入口场景 | 路口布局、入口用途、阻挡形状、公开信息、正式选项 ID | 布局要允许真实到达；触屏、键盘都可完成；不另写价格与时钟 |
| 路边可选事件 | 出现位置、接近窗口、主动接受动作、任务 ID | 不主动接受不收费；离开不反复弹出；接受后有实际后续效果 |
| 人物压力 | 学生诱惑／公司通知／游客方向知识／孩子距离与怒气 | 人物压力必须由实际状态影响操作和决策，不能只换一段弹窗文案 |
| 结果反馈 | 正式日志、碰撞／避障、真实资源变化、估算时间收益 | 局部入口运动不伪记主路段躲障碍；剧情积分不进入赶车属性 |
| 预算与验证 | 正式初始预算、准备、路线、操作档、独立种子 | 输入机制改了就更新模拟；旧版本成功率不得作为新机制验收 |

每次迁移都按任务成本收益的交付模板补齐成本、实际收益、边界、消费者和验证。先完成一个可观察、可操作、可结算的完整链路，再复制到其他站。

## 6. 实际交付与验证记录

当前代码已提供 `spatialChoice.ts` 的六类场景定义与碰撞运动、`SpatialChoice.tsx` 的按住地面／拖动引导／方向键与WASD输入：上楼入口、三扶梯、长廊、安检队列、大厅方向、八条检票通道。入口不是选择按钮，必须用实际移动进入；位置读取 `eventElapsed` 增量，安检观察也读取同一时钟。几何模型不修改资源和费用，到达调用当前事件的正式 `CHOICE`。`hongqiao.ts` 与站内流程将四诱惑接成可路过热点，并记录普通步行是否可自动恢复。专项和完整输入验证的范围分别如下。
