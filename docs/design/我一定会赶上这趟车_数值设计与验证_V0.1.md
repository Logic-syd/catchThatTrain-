# 我一定会赶上这趟车：数值设计与验证 V0.1

日期：2026 年 10 月 9 日  
状态：本地修复分支的实现记录与调参依据，待真实试玩验证  
对应分支：`codex/bugfix-mobile-flow-events`

**数值要支持的体验是：我一直急着跑，但人群、设施和自己的状态不断打断我；处理完还能继续争取赶上。** 地图中的距离、绕行和阻挡是主玩法，时间与资源负责让处理方式产生不同后果。

这份文档单独记录计算口径、当前参数、可复现结果和还没有解决的取舍。它与[设计对齐稿](./我一定会赶上这趟车_设计对齐稿_V0.1.md)配合阅读，不改写原始设计文档，也不代表这里的调参已经发布。

## 1. 时间怎样计算

必须区分两种单位：

| 单位 | 用途 |
| --- | --- |
| 现实秒 | 玩家读题、按住按钮、点击、等待动画实际经过的时间；体力消耗与恢复按这个单位计算 |
| 游戏秒 | 倒计时中的秒数、路线预算、选项显示的时间代价、结算损失 |

当前流程的计时：

- 地铁行驶合计约 7 个现实秒，按照路线进度扣除对应的游戏行程时间。每站开门最多 4 个现实秒，到站决策时间另计。
- 站内实际移动：1 个现实秒对应 4 个游戏秒。地图长度与各站步行预算对应，再由人物速度、冲刺和路线变化影响实际耗时。
- 安检排队：以 4 倍游戏时间逐个放行；换队后重新排。A、B、C 队同时推进。
- 读题、操作、普通事件等候、停下休息：按正常速度计时。
- 选项的固定代价在确认时扣一次。例如“−5 秒”是一次固定代价；玩家读题花的时间另外自然经过。
- 遇到小孩等阻挡，展示已经真实经过的时间，不再额外扣一笔相同的损失。

检票停止时间比发车早 180 个游戏秒。因此，初始“距离停止检票”预算是 `initial − 180`。通过检票后，最后登车仍受发车倒计时约束。

计时记录不能直接把所有日志、自然计时和估算相加：有些日志只是对已发生损失的解释。大学生的校验账本使用“自然经过 + 选择代价 + 环境损失”与倒计时实际减少量对照。

本轮已修复延迟帧问题：地图上的较大时间步拆成 0.1 秒推进，避免扣了整段时间、小人却只走一小步，或越过障碍检测。无效时间步不推进游戏。

## 2. 初始预算来自路线与人物

一般计算方式：

```text
初始距离停止检票预算 =
  向上取整到 30 秒（可行地铁路线预算 + 站内步行参考 + 决策缓冲）
  − 困难模式削减
```

以可行的较快路线作为起点，避免按最慢路线发时间、选快路线后轻易剩下数百秒。站内步行参考会考虑人物；大学生使用车站标准步行时间，打工人、游客和家长按初始移动能力补偿。准备、读题、障碍、绕路仍会消耗这份预算。

## 3. 体力、冲刺与疲劳

| 人物 | 初始能量 / 上限 | 冲刺基础耗能，每现实秒 | 走路恢复 | 停下恢复 |
| --- | ---: | ---: | --- | --- |
| 大学生 | 90 / 90 | 8 | 基础 2.2，受上限、负重与最后阶段修正 | 基础 5，同样受状态修正 |
| 打工人 | 60 / 60 | 5 | 1.15 / 秒 | 3.5 / 秒 |
| 游客 | 35 / 35，初始疲劳 70 | 6 | 基础 0.9 / 秒，受疲劳修正 | 基础 4.5 / 秒，受疲劳修正 |
| 家长 | 70 / 70 | 4.6，抱孩子时 5.6 | 未抱孩子 +0.55 / 秒；抱着 −0.55 / 秒 | +1.15 / 秒 |

打工人基础速度 0.9、冲刺速度 1.65；游客 0.86 / 1.55。实际速度继续受到当前能量、负重、疲劳等状态影响。游客高疲劳降低恢复速度，不能反而减少冲刺耗能。

能量耗尽后只能慢走或停下恢复，不能把人物锁死。重新允许冲刺的恢复门槛：大学生 15，打工人和游客 10，家长 12。

大学生另外有“冲刺负荷”：持续冲刺累计到 7 个现实秒会岔气，需要操作调整呼吸，并付出 105 个游戏秒。慢走每现实秒缓解 1.5，主动停下缓解 2；事件处理时不自动清空负荷。界面在到顶前给预警。

带小蛋糕不增加体力：专注 +5、负重 +5；走路额外消耗 2.7 / 秒，冲刺额外消耗 2.2 / 秒，占手也增加部分操作负担。不带专注 −5。最后阶段大学生的冲刺和恢复增强是翻盘机会，不能让全程乱冲成为最优解。

家长还要考虑孩子：未抱时冲刺会增加距离差，抱着跑会更耗家长体力；孩子体力、耐心与尿意分别变化。尿意按游戏分钟增长：站内 4.5、地铁 1.8、其他阶段 0.45。提前上厕所归零；站内再去需要 75 个游戏秒。

对应实现：[studentConfig.ts](../../src/studentConfig.ts)、[characterTime.ts](../../src/characterTime.ts)、[parent.ts](../../src/parent.ts)。

## 4. 选项必须有具体意义

不能简单设计成“第一项花时间，第二项直接走”，也不能为了让两项看起来公平，就给每项硬塞一个扣时。

| 选择 | 当前效果 | 为什么可能选它 |
| --- | --- | --- |
| 大学生带蛋糕 | −75 秒，专注 +5、负重 +5，护蛋糕消耗体力 | 情感、专注和相关成就，主动承担负担 |
| 不带蛋糕 | 专注 −5 | 赶时间、保持双手空闲，但会走神 |
| 提前找身份证 | −30 秒、专注 +10，记住前袋 | 检票时定位更明确，减少翻错与操作压力 |
| 到检票口再找 | 未确认位置，需要按线索翻夹层 | 留出眼前进度，承担之后找证件的压力 |
| 大学生吃饭团 | −60 秒，提高能量上限；初始 90 受总上限 100 截断，实际 +10 | 保持后程上限；界面展示实际收益 |
| 直接走 | 到候车大厅能量上限 −10 | 留住眼前时间，后程更易耗尽 |
| 打工人再吃两口 | −60 秒、体力上限 +10、补充 10 体力 | 满 60 体力时也能变成 70，收益真实生效 |
| 答应老板今晚发 | 体力 −10，暂时清静 | 用资源换少受工作干扰 |
| 不理老板 | 之后可能来电 | 保留当前体力，承担后续打扰 |
| 游客喝咖啡 | −50 秒、疲劳 −15；精力恢复受上限约束 | 减少疲劳，让后续移动与恢复更容易 |
| 修箱轮 | −20 秒、负重 −5 | 改善后续移动，文案与状态一致 |
| 硬拖箱子 | 精力 −3、疲劳 +3 | 当下继续走，承担资源损失 |
| 出发前孩子上厕所 | −60 秒、尿意归零 | 减少路上临时绕厕所的风险 |

数值上已经生效，不等于取舍已经足够好。脚本里吃饭、咖啡仍有收益弱的问题，见第 7 节。

方向判断题与资源取舍题也要分开：清楚写着“铁路出发”的正确通道，可以比“到达出口”更好；关键是线索必须在游戏里读得懂，不要求住过这座城市。体力换近路、距离换少人，才需要在不同状态下出现不同的合适选择。

## 5. 没听清地铁报站：体力换把握

按最新讨论实现为：

| 选项 | 即时代价 | 后续 |
| --- | --- | --- |
| 不管哪站，先去门口等着 | 时间 −5 秒、体力 −5；游客显示精力 | 靠门留意站名，不触发这道题的坐过站风险；到站仍要下车 |
| 老实坐着，等下一站 | 时间 −5 秒，保留体力 | 可能坐过站；真的发生时折返耽误 50 秒 |

玩家看见的是动作、资源与可能的后果，**不展示任何概率数字，也不提前泄露本局抽到的结果**。路线页、帮助与老人事件同样遵循这个规则。

内部调参：`BALANCE.metroAnnouncement` 固定代价 5 秒、靠门耗能 5、折返 50 秒，坐着等待的风险参数暂定 0.3。这里只供开发调参，不写进游戏界面。随机结果在创建本局时抽一次，重新渲染、读题或切换画面不重抽。

这道题发生在目的站前的最后一段，避免在无关中间站提前判“坐过站”。实际发生折返才扣 50 秒，恢复画面自然经过的时间另计；之后改去门口会再付 5 秒、5 能量，不能通过原来的免费靠门按钮消掉风险。

内部期望固定时间代价为：去门口 5 秒；坐着等待 5 + 0.3 × 50 = 20 秒，但后者保留 5 能量。这个计算只说明成本，不证明两项已平衡。若体力总能很快恢复，去门口可能仍明显更有利；需要看低体力局、时间紧迫局的选择，而不能只调概率来掩盖问题。

对应实现与用例：[metroFlow.ts](../../src/metroFlow.ts)、[metroAnnouncement.test.tsx](../../src/metroAnnouncement.test.tsx)。

## 6. 可复现自测结果

本轮普通模式跑了两组各 576 局：4 人物 × 6 车站 × 3 种赶路策略 × 8 个固定种子。一组路线判断正确，另一组增加一次站内方向错误。每次读题预留 5 个现实秒，操作按实际长按、点击与等待时间执行。

三种策略是慢走、分段冲刺、一直冲刺。分段策略以“冲 4 秒、走 3 秒”为基础，并考虑低体力、冲刺负荷与孩子距离。它知道路线和队伍成本，不能当成真人首次游玩。

大学生结果：

| 车站 | 分段冲刺剩余检票时间 | 多一次方向错误后 | 一直冲刺 |
| --- | ---: | ---: | ---: |
| 上海虹桥 | 105–151 秒 | 52–98 秒 | 0 / 8 通过 |
| 北京南 | 85–99 秒 | 33–47 秒 | 0 / 8 通过 |
| 广州南 | 150–157 秒 | 96–103 秒 | 0 / 8 通过 |
| 杭州东 | 84–85 秒 | 41–42 秒 | 0 / 8 通过 |
| 武汉 | 100–107 秒 | 47–55 秒 | 0 / 8 通过 |
| 郑州东 | 85–91 秒 | 33–39 秒 | 0 / 8 通过 |

分段冲刺在上述两组各站均为 8 / 8 通过。一直冲刺在标准准备组合下六站合计 0 / 48，通过呼吸预警和岔气体现无脑冲的代价。大学生时间账本误差为 0（报告精度 0.01 秒）。

其他人物正确路线、分段冲刺：

| 车站 | 打工人剩余时间 | 游客剩余时间 | 带娃家长剩余时间 |
| --- | ---: | ---: | ---: |
| 上海虹桥 | 28–69 秒 | 25–61 秒 | 25–63 秒 |
| 北京南 | 55–61 秒 | 91–101 秒 | 92–99 秒 |
| 广州南 | 39–46 秒 | 33–42 秒 | 9–16 秒 |
| 杭州东 | 59–62 秒 | 77–78 秒 | 47–49 秒 |
| 武汉 | 77–78 秒 | 66 秒 | 85 秒 |
| 郑州东 | 39–46 秒 | 44–49 秒 | 64–68 秒 |

各项均 8 / 8 通过，但家长广州南余量偏小。多一次方向错误后，打工人和游客在广州、郑州的这套策略均失败，说明后续关卡的容错很窄；不是已经验证“难度合适”。

汇总数据保存在 [balance-report.json](./balance-report.json)。固定种子从 921 开始，每局增加 83。报告里的真人成功率没有估算；其他人物尚未建立与大学生同样的完整分类账本，报告中的非大学生账本字段不能当成核账证明。

## 7. 还需要调的地方

同样种子、同样赶路策略，只换一个准备选项：

| 对比场景 | 保持原准备的剩余时间 | 换另一项后 | 当前结论 |
| --- | ---: | ---: | --- |
| 大学生上海：检查身份证 / 到站再找 | 105–151 秒 | 112–168 秒 | 再找多翻错 0–3 次，但这组策略仍更省时间；检查的操作便利未抵回 30 秒 |
| 大学生上海：吃饭 / 直接走 | 105–151 秒 | 165–211 秒 | 对分段冲刺而言，上限收益不足以抵回 60 秒 |
| 大学生上海：不带 / 带蛋糕 | 105–151 秒 | 22–61 秒 | 护蛋糕确实增加负担；目前主要是情感、专注与挑战价值 |
| 打工人上海：吃饭 / 直接走 | 28–69 秒 | 79–119 秒 | 上限增益已生效，但在这组策略中仍不如直接走 |
| 游客广州：咖啡 / 直接走 | 33–42 秒 | 62–72 秒 | 减疲劳有实际收益，但不足以抵回 50 秒 |
| 家长广州：提前厕所 / 路上再去 | 8 / 8 通过，余 9–16 秒 | 0 / 8 通过 | 后补厕所的负担很重，应复查广州余量 |

这些结果说明“选项都有状态变化”和“玩家有理由选不同项”是两件事。下一步应优先验证吃饭、咖啡、查证件的收益与耗时，尤其在短站和长站、操作熟练和首次阅读之间是否有不同价值。不要只改文案，也不要把其他选项惩罚到必输。

当前修改已解决满体力吃饭无实际收益、修轮子不改负重、耗尽不能继续走等计算问题。尚未证明所有选项都有足够吸引力；复杂模式与所有准备组合也没有穷举。

### 补充：成功率是否仍然偏高

针对“成功率是不是还是太高”增加了 1,008 局大学生敏感性计算：7 组读题／准备／失误情境 × 6 站 × 8 种子 × 3 档预算。它只比较同一套操作下参数的影响，仍然知道最优路线和队伍，不能据此声称真人通关率。

当前预算、分段冲刺：

| 情境 | 通过局数 | 通过时剩余检票时间 |
| --- | ---: | ---: |
| 每题读 5 秒，不带蛋糕、查证件、吃饭，不走错 | 48 / 48 | 84–157 秒 |
| 每题读 8 秒，同样准备，不走错 | 48 / 48 | 36–109 秒 |
| 每题读 8 秒，同样准备，走错一次 | 24 / 48 | 1–57 秒 |
| 每题读 8 秒，不带蛋糕、不查证件、不吃饭，走错一次 | 48 / 48 | 36–143 秒 |
| 每题读 8 秒，带蛋糕、查证件、吃饭，走错一次 | 0 / 48 | — |
| 每题读 12 秒，不带蛋糕、查证件、吃饭，走错一次 | 0 / 48 | — |

**“全部跳过准备”优势过大，额外携带蛋糕的负担又过重。** 这比总成功率更值得先处理。只把所有站的开局时间减少 30 秒，查证件、吃饭、读题 8 秒且走错一次的情境降到 12 / 48；跳过准备的同类情境仍然 48 / 48。统一缩短倒计时会扩大准备选择之间的差距。

当前机制可以解释这种现象：大学生吃饭主要提高体力上限；读题与处理事件时可以恢复体力，分段冲刺也避开耗尽，上限优势不容易兑现。提前查证件固定花 30 秒，而该组脚本里的现场寻找通常没有耗掉这么久。带蛋糕同时付出 75 秒、负重、占手和持续耗能，专注收益补不回这些成本。

据此，下一轮优先顺序是：让吃饭与提前查证件在对应状态下有足够实际收益；检查护蛋糕的持续消耗，保留可以追回来的余地；再根据六站余量单独调整预算。真实首玩约 75% 仍需试玩样本验证，不能挑选或混合脚本情境凑出这个比例。本次只补充诊断，没有应用模拟中的 −30／−45 秒方案。

完整情境与逐站结果见 [balance-sensitivity-report.json](./balance-sensitivity-report.json)，复现脚本为 [balanceSensitivity.ts](../../scripts/balanceSensitivity.ts)。其中“走错两次”是最多制造两次方向错误，有些站只有一次符合条件的方向决策；结果保留了实际错误次数。

## 8. 怎样继续验证与调参

在项目目录运行：

```sh
npm run test
npm run build
npm run balance -- --reading=5
npm run balance -- --reading=5 --mistakes=1
npm run balance:choices
npx vite-node scripts/balanceSensitivity.ts
```

`BALANCE_SAMPLES` 可以调整每组种子数，`--hard` 检查困难模式，`--details` 输出逐局数据。若系统默认 Node 版本太旧，先使用项目可用的 Homebrew Node。脚本在 [scripts](../../scripts) 中，只做数值情境验证，不模拟手机触控手感。

真人首关约 75% 通关率仍是目标，没有被脚本证明。后续试玩至少记录：首次还是重玩、人物与站点、准备与路线、冲刺习惯、读题或找按钮的卡点、通过时余量、失败原因。先收集一批首次游玩，再按原因分组调整；不能把 8 / 8 的已知解法自动化结果写成“玩家成功率 100%”，也不能把此前 3–5 人反馈当作精确统计。

界面始终只表达玩家需要知道的事：醒目的真实代价、实际可获得的收益、延迟生效条件、可能遇到的风险。随机参数留在内部，选项初始同色，选择后才给结果反馈。

## 9. 每站、每个人物都有容易误判的选项

最新调整覆盖六站与四个可玩人物，共 24 组核心情境。利用近、人少、人群走得熟、编号相似等直觉制造诱惑。线索仍在路牌、人流方向、行李与现场动作里；玩家不需要现实城市经验。

| 车站 | 大学生容易被什么吸引 | 打工人容易被什么吸引 | 游客容易被什么吸引 | 家长容易被什么吸引 |
| --- | --- | --- | --- | --- |
| 上海虹桥 | 同款背包的人挤进商店，觉得自己也能挤 | 跟着前面拖箱子的省几步 | 腿酸，近在眼前的商店门头 | 孩子喜欢亮堂商店，也想少走一点 |
| 北京南 | 背包小，空门看着能直接进去 | 老板消息催着，想先从空门进去 | 两个门很像，凭人少来判断 | 孩子站不住，想少排一段 |
| 广州南 | 相信自己能跑过中区人流 | 相信同样拖箱子、声称常来的热心人 | 有人主动带路，省得继续认地图 | 别的抱娃家长都走中区 |
| 杭州东 | 左侧人群都在小跑，像是也在赶车 | 分心看工作消息，跟通勤人流走 | 陌生车站里，人多的一边更安心 | 左侧商店和人流一起吸引孩子 |
| 武汉 | 被催着“先上一层再说” | 跟着搬货车和大箱子去一层 | 已经看见一层大厅，不想再爬 | 孩子喊周黑鸭、店主又催着让路 |
| 郑州东 | 记住了数字，却把 12 和 21 看反 | 熟悉口音的老乡招手带路 | 相似大厅里更依赖有人指路 | 孩子指着左侧号码，老乡也招手 |

具体现场线索包括：商店有人停下取餐；北京东门“只出不进”；广州连桥标识沿同一层延伸；杭州牌子区分到达与铁路出发；武汉楼层牌写明 1F 到达、2F 出发；郑州保留车票与两侧分区数字。家长的杭州电梯还增加“楼层灯亮着”的诱惑，维修牌与上个月坏掉的记忆仍可见。

选择展示与结算分开：

- 选择前不再直接写“折返 45 秒”“这条更快”等已知结果；展示眼前能观察到的情况。
- 选择后展示实际时间损失，并解释原因，例如“跟来的人是出站通勤，已从到达出口折回”。地图路线、后续换层和资源效果继续真实生效。
- 明确的准备成本和已知资源取舍仍然展示，例如带蛋糕的 75 秒、专注与负重；本轮没有把所有属性数字隐藏。
- 普通选择题在每局内固定显示顺序，新局的首项可以变化。读题期间不跳位置；A/B/C 队、编号闸口保持空间顺序，按钮初始同色。
- 检票通道改看距离、人数和现场动作，不提供精确排队秒数。两个人可能还在翻包，三个人可能已把证件拿好；人数图标不再根据隐藏耗时推算。

实现集中在 [decisionPresentation.ts](../../src/decisionPresentation.ts)，实际后果进入日志与操作完成提示。所有 24 组都验证诱惑选项能被选择、实际效果仍执行、结果在选择后才显示。误导的作用是让判断更有参与感；真人成功率如何变化，仍需新一轮试玩。


## 10. 至少 12 次有效操作、容错递减与途中预警（10 月 9 日修订）

这次“容错率逐级降低”按人物解锁顺序理解：大学生 → 打工人 → 疲惫游客 → 带娃家长。这里的“一局至少 12 次”指完整通关流程；如果在地铁途中已失败，操作次数可以少于 12。

### 有效操作的口径

一次有意义的选择或完整动作算一次：出门准备、选线路、认方向、在正确站下车、选安检队、放包过安检、确认路线、选检票通道、刷证、登车。按住按钮、向上滑动或连点三下才能完成的动作，都只计一次。等待动画、每帧移动、反复按冲刺、重复点击、翻错夹层、同一轮反复换队不增加次数。

最短的杭州东流程中，两次准备 + 选线路 + 认方向 + 下车 = 5 次；站内选择出发方向 + 选安检队 + 放包 + A/B 分区判断 + 选检票通道 + 刷证 + 登车 = 7 次，合计 12 次。大学生多一道准备，其他站还有换层、阻挡和人物事件。即使身份证已经提前拿好、走了可用近路，最低仍为 12 次。没有新增用来凑数的空白确认页；路上的阻挡、地图改道和赶路手感继续保留。

回归检查同时验证 24 组人物与站点的最小结构，以及实际完整流程的有效操作记录。结算展开“本局表现与时间明细”可查看实际次数。

### 递进的失误代价

初始预算、已经明示的准备成本、地铁报站的 5 秒与可能追加的 50 秒保持各自规则。对站内**有明确折返代价的方向误判**，按人物层级放大，向上取整到 5 秒。人少、跟人流、亮灯等诱惑仍保留；选择前不泄露结果和随机概率。

| 人物 | 方向误判倍率 | 原本 45 秒的折返 | 原本 55 秒的折返 |
| --- | --- | --- | --- |
| 大学生 | 1.0 | 45 秒 | 55 秒 |
| 打工人 | 1.2 | 55 秒 | 70 秒 |
| 疲惫游客 | 1.4 | 65 秒 | 80 秒 |
| 带娃家长 | 1.6 | 75 秒 | 90 秒 |

这不是所有坏结果的统一倍率。排队、路障等实际经过的时间照常推进；正确方向不追加惩罚。上海商店通道与广州中区的代价仍由距离、人流、换层和人物状态产生，不另加一笔虚构的“选错罚时”。

### 途中比较的判定

进入站内后，顶部并排显示“检票还剩”与“到检票口理论最短”；检票成功后切换为“发车还剩”与“到车门理论最短”。停止检票早于发车 180 秒，两个阶段使用不同截止时间，不能混用。

计算从玩家当前地图位置出发，考虑实际道路、剩余任务、已经选择的路线，以及后续仍可用的近路和换层分支。地图距离与行走秒数继续使用游戏本身的换算。广州绕外侧跳过电梯、楼梯跳过扶梯选择、北京地图安检已完成托盘等，不能重复计入。

为了让“肯定赶不上”可信，比较的是**极其乐观的时间下限**：允许人物一直保持理论最高速度，暂不计未来排队、读题、恢复体力和随机阻挡。因此它不是推荐跑法，也不是平均预计到达时间，更不表示能一直按住冲刺。普通步行估时不用于判死。

- 余量超过 60 秒：提醒“抓紧，路上还会耽搁”。
- 余量 0–60 秒：提醒“余量很少，别再走错”。
- 剩余时间少于理论下限：标红“这趟肯定赶不上了”，说明连理论最快也来不及；允许继续走完这趟，不自动结算。

下限向下取整，剩余时间向上取整，避免仅因显示取整误判。预警不修改倒计时，不额外扣时，不抽随机数，不透露哪个选项正确。只在站内展示比较；地铁和准备阶段沿用原倒计时。结果页原有普通估时用于复盘，与这个严格乐观下限区分。

### 本轮验证

最新结果在 [balance-progression-report.json](./balance-progression-report.json)，运行 `npm run balance:progression` 可复现。固定每题读 5 秒、分段冲刺、正确准备、已知路线与队伍，六站各 8 个种子；分别检查不走错和主动走错一次，共 384 局。

| 人物 | 不走错的完成局数 | 主动走错一次后的完成局数 | 不走错通关的有效操作次数 |
| --- | --- | --- | --- |
| 大学生 | 48 / 48 | 48 / 48 | 18–26 |
| 打工人 | 48 / 48 | 18 / 48 | 18–27 |
| 疲惫游客 | 48 / 48 | 16 / 48 | 19–29 |
| 带娃家长 | 48 / 48 | 8 / 48 | 18–28 |

这些是已知解法的固定情境结果，不是真人首次通关率，也不要求每一站容错完全相同。大学生仍可救回一次方向错误，后续人物更难挽回。此前第 6–7 节及旧报告保留为递进调整前的基线；涉及后续人物方向错误的结果以本节新报告为准。首关真人约 75% 的目标还需要继续试玩验证。

另有完整 24 组流程的途中采样：每次事件/队列状态变化及每 5 秒，核对理论最短不大于该局实际剩余用时；成功局不应收到“肯定赶不上”提示。分支规则集中在 [journeyRules.ts](../../src/journeyRules.ts)，预警在 [raceForecast.ts](../../src/raceForecast.ts)，操作计数在 [meaningfulOperations.ts](../../src/meaningfulOperations.ts)。
