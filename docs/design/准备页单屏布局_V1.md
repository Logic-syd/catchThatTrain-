# 准备页单屏布局 V1

日期：2026-10-17。基于 `main@6b9a1b1`。范围：学生、打工人、游客、带娃家长的出门准备页，中英文显示。

**现行显示以文末“短文案与百分秒修订”为准**：保留一屏布局，按用户后续反馈移除属性面板与长说明。下方首次单屏记录保留作比较。

## 首次单屏调整（历史记录）

准备页按浏览器可用高度布局，倒计时、准备步骤、标题、故事、属性、全部选项及完整成本收益同屏显示。图标与标题同行，四项属性横排；收紧卡片与区块留白，小高度视口让装饰箭头的位置给选项全文。详情字体保持12px，文字可正常换行，没有省略号、行数截断或内部滚动容器。

进入准备页时立即回到顶部，避免继承首页滚动位置。起飞车票的装饰动画在准备页不盖住属性和选项，仍正常完成自身清理。修改集中于 [preparation.css](../../src/preparation.css)、样式入口和页面切换时的滚动位置。

本轮没有新增准备任务或修改选项文案、ID、费用、资源、上限、消费者及计时。`PREP_PICK`、`PERSON_PICK`、`PARENT_PREP` 使用原有回调，双语仅切换显示；原有准备费用和实际收益仍由规则计算后完整显示。

## 验证口径

手机尺寸使用**网页可用视口**，不把系统状态栏、浏览器或微信顶部工具栏算作可展示内容。验证覆盖320×568、375×600、375×667、390×650、390×700、390×750及1440×900。系统放大字体等超出此矩阵的情况保留正常文档流，优先让内容可访问，不用强制裁切伪造无滚动。

浏览器使用真实 App：从首页选择人物、出发，逐步点击准备选择，中英文来回切换后检查步骤保持，最后进入路线页。检查整页与内部滚动、首屏边界、文字完整性、按钮可点击、反馈遮挡和运行错误。准备有不同费用的合法选择，不把检查用的预设解锁当作正常解锁流程证据。

本轮不改变输入机制或数值模型，不重新发布模拟成功率。继续遵循[任务成本收益](./任务成本与收益规则_V1.md)和[双语显示规则](./中英双语显示规则_V1.md)。

## 短文案与百分秒修订（现行，2026-10-17）

用户反馈文字过多、不想读，因此准备页改成“一个问题＋短操作＋一条主要取舍”。不再展示属性点阵、资源上限、恢复百分比、来源故事区和重复说明；各页统一保留“时间一直在走”。例如奶茶选项显示“买一杯 / −45 秒 · 提提神，但占一只手”。人物口吻留在标题里。

### 后续准备文案约定

- 标题尽量一句，操作尽量一小句；详情只写正式耗时和影响选择的主要收益／代价。中文与英文分别写短句，不为了逐字翻译恢复长段落。
- 已知固定耗时必须披露，由原选项 `seconds` 生成，不能另写一套秒数。零费用写“不额外耗时”，表示没有额外选择费用，读题时间仍照常推进。
- 隐藏属性计算不等于隐藏重要取舍：奶茶占手、纪念品加重、空腹后续饥饿、老板可能追问、孩子途中找厕所仍要说清。库存次数可以展示；不再逐项展示敏捷、专注、精力等数值。
- 短句必须有真实消费者，不承诺固定节省时间或虚构恢复。若未来某个可达状态已没有实际收益，应改成对应的简短状态提示，不能继续承诺收益。
- `preparationCopy.ts` 仅按任务／选项 ID 映射显示文案，标题和选项原始数据、日志与提交值不改。新任务或新选项未写短句时保留原文和原费用；新增时同步完成短句、英文、实际效果与小屏检查。
- 这是准备页的简短显示约定；完整资源计算与边界仍遵循[任务成本收益](./任务成本与收益规则_V1.md)及[准备资源规则](./准备收益与任务资源规则_V1.md)，不把 UI 省略的信息从引擎删除。

### 任务与收益链路

作用范围是四个人物全部车站的出门准备，共10步：学生 `tea/id/breakfast`，打工人 `worker-0/1/2`，游客 `tourist-0/1`，家长 `parent-0/1`；选项 ID 和 `PREP_PICK/PERSON_PICK/PARENT_PREP` 提交保持原样。仅显示层创建短文案副本，不改变任务效果、资源边界、固定等待结算或初始预算。

付费选择仍从原规则读取45/10/25秒（学生）、60/20秒（打工人）、50/30秒（游客）、60秒（家长）；其他准备没有额外固定费用。奶茶的提神与占手继续用于恢复／移动与双手操作；检查身份证继续记住前袋；吃饭继续提供饱腹或移动储备；咖啡／休息继续缓解疲劳；行李选择影响负重；回复消息只消除原消息追问；厕所准备推迟尿急；两份零食供后续安抚消费。费用日志、重复提交防护和结算归因沿用原规则。

### 倒计时

活动中的 HUD 显示 `分:秒.百分秒`，例如 `28:27.36`，小数位缩小且数字等宽。它直接读取同一个 `remaining − 停止检票预留`（检票后读取 `remaining`），跟随原有100ms更新。没有新增定时器、插值、随机数字或第二套扣时；显示精度是0.01秒，刷新频率仍约每秒10次。

用同一个向上取整的百分秒值拆分分钟、秒与小数，避免整数秒和小数分别取整错位；截止后钳制为 `00:00.00`。朗读不实时播报每次跳数。日志、结算与其他分钟显示继续使用原来的 `formatTime`。

## 场景化准备修订（2026-10-17，替代独立大图标）

用户指出页面仍像表单，独立放大的图标没有解决大块留白和缺乏场景的问题。大学生三步准备统一改为“倒计时 → 准备进度 → 场景 → 决策区”：奶茶店、背包检查和早餐摊分别对应三个步骤；人物、街道、店招、杯身和地铁方向牌组成画面。三种奶茶图形放进店招与杯身，不再单独悬在标题上。场景是装饰，不伪装成需要额外点击的任务；两项原有选择保持可直接操作。

决策区保留一句问题、两项短选择和真实费用，暖色／绿色区分两个操作，步骤进度同步读取 `student.prep`。未增加输入次数、等待时间、奖励、预算或新引擎状态。英文新增店招文本并沿用现有准备翻译。仅大学生准备布局采用场景版，其他人物仍保留此前布局。

生产构建通过，资源收益与双语既有测试共26项通过。Chromium真实App检查三种图形对应车站 × 两语言 × 三步 × 320×568、390×650、390×844、1440×900，共72个状态：无整页横纵溢出，场景、标题、全部选项在屏内；每步保持两个选择，奶茶显示原45秒费用，点击可依次进入下一步和路线页。另人工检查最终320px与390px截图。证据在 `/workspace/scratch/auto-run-browser/prep-scene.json`、`prep-scene-*.png` 和 `scene-final-tall.png`。不将显示验证当作难度复测。
