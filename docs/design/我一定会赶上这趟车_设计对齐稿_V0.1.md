根据你最新的纠正，核心体验应当是：**我急着冲向检票口，但前面的人和设施不断阻碍我；刚想跑起来，又得借过、刹住、绕行或等放行。** 站内地图和这段连续赶路是主要玩法。准备、地铁、数值和结算都围绕它服务。

“一直想冲”表达的是玩家的急迫感，不代表全程按住冲刺就能穿过所有人。要让玩家记住“是谁堵了我、我怎么过去的、终于又跑起来了”，而不只是扣了多少秒。

这份稿把你已经明确提出的要求、我的设计理解和当前代码的不足分开列出。原始文档保留不动；下面写“目标”或“待确认”的部分，不代表已经实现或经过试玩验证。若与旧稿冲突，以你后续明确的调整为准。

## 已经明确的方向

- 手机优先，一局是短时间的赶车经历。原先约 3–5 分钟是体验目标，仍需按实际试玩核对。
- 每轮从六站随机给出两个候选，玩家自己选赶哪一趟。
- 新玩家从大学生开始，成功后依次解锁打工人、疲惫游客、带娃家长。通关资格永久保留；失败可以中断连胜，不能收回人物。
- 站内以地图为主体，玩家在通道、路口和设施之间移动，沿途遇事。地图要清楚、有分支、有地标，不应做成难认的迷宫。
- 玩家既要选择，也要操作。背包挂住、安检没完成、孩子掉队等，必须真的挡住前进。
- 随机制造局面，玩家决定处理方式。随机与选择共存，不能靠随机扣时替代玩法。
- 手机操作区固定在底部，按钮足够大，可以遮住部分地图；不能让玩家为了做当前操作上下找按钮。
- 每项选择都要交代有意义的后果。时间、精力、专注、负重、后续风险都可能是代价；不能只把扣时间做醒目。

## 一局应该怎样展开

| 阶段 | 玩家要解决的问题 | 画面与反馈 |
| --- | --- | --- |
| 开局 | 我是谁，为什么又晚了；这次选哪一站 | 左上卡通人物像在说“我一定会赶上这趟车”；简洁背景、属性、难度星级和两站选择；开始按钮易找到 |
| 出门准备 | 现在花时间准备，还是带着问题先走 | 每题有具体生活场景；选完显示结果，再明显进入下一题；不能三题像同一张静止页面 |
| 地铁路线 | 少换乘、少步行、行程更短，哪个更适合这个人 | 路线的主要差异提前可见；上车方向、换乘站与下车站都有可读线索 |
| 地铁途中 | 意外怎么应对；这一站要不要下；是否补觉、提前靠门 | 选择的路线真正影响停站；游客睡着后跳到预设叫醒站，醒来再判断 |
| 站内地图 | 走哪条通道，何时冲刺，怎样处理路上发生的事 | 小人在实际地图上移动；到路口看牌，到障碍前停下；选择改变后续处境 |
| 检票和登车 | 找对编号、拿证件、刷卡、完成最后一段 | 证件、闸机、列车有不同操作和反馈；前面的准备此时兑现 |
| 结算 | 我这局是怎样赢或输的，还解锁了什么 | 大结果和称号先出现，随后是短标签、关键原因、成就和分享；细节折叠 |

节奏上应有“出发时乐观—途中开始紧张—最后争取翻盘”的变化。事件之间要留出能感受到移动的时间，不能变成一张地图配一长串连续弹窗。

## 地图和事件各自负责什么

地图负责空间关系和真实阻碍：我在哪里、眼前是谁、还有哪条缝能过、目标检票口在哪边。先确定目的地，按住“赶路”沿连接的通道前进，换按“冲刺”加速，松手停下喘气；玩家可以改道、回头，在空隙里冲刺。遇到普通阻碍后保留原目的地，处理完提示按住继续，避免每挪几步都要重新点“下一任务”。直接按住赶路也可以以列车为目标出发，仍需依次完成安检、检票等设施。

事件负责制造局面：人挡住了、箱子卡住了、安检要拿出东西、老人搭话、孩子要抱。触发后，地图中的人物停住，底部出现与这件事对应的选择或操作。处理过程能看见变化，例如背包被提起、托盘送进去、闸门打开；完成后明确提示结果和接下来的地点。

我建议把事件分成三类：

| 类型 | 例子 | 触发原则 |
| --- | --- | --- |
| 必须通过的设施 | 安检、检票、登车 | 流程必须完成，但每次操作可以受人物和准备影响 |
| 路线与状态事件 | 走进拥挤通道、老板来电、孩子掉队 | 由玩家走到的区域、先前选择或实际状态触发 |
| 随机遭遇 | 背包挂住、有人挡路、扶梯拥堵 | 随机决定是否遇到、遇到哪种情况，之后仍有处理空间 |

**本轮补上的局部体验：** 人群堵车门、扶梯出口停步、横穿小孩、支路人群和关闭的人工窗口已经放入实际地图的行进检测；命中会停在面前，借过、等候、侧身绕行有不同的过程。中区／商店通道的人群与外侧路径分开，改道会影响是否经过它。安检改为选队、逐个放行、放包，而非选完直接扣一笔时间。目的地可以跨过处理过程保留，放行以后衔接原路线。

**仍需完善的部分：** 证件、路牌、人物特色等多数较长任务仍按阶段安排。当前人群是本局固定的位置配置，配合一个往返移动的小孩；还没有完整的多行人自主移动、互相避让和电梯上下客模拟。原有地图节点也是抽象通道，没有精细站内建筑碰撞。这一轮是可试玩的阻挡循环，需要按实际手感继续调人群密度、路宽和遭遇节奏。

事件是否提前用标记全部显示、哪些应当靠近才出现，也需要确认。建议必要设施常驻地图，随机遭遇只在接近时给出可反应的预警。

## 站内赶路的主要体验

你给出的五种局面，是这一段的基本设计依据：

| 眼前发生的事 | 玩家实际受到的阻碍 | 能做的操作与后续变化 |
| --- | --- | --- |
| 地铁门开了，前面的人还没走 | 小人停在前面的人身后，按住冲刺也穿不过去 | 说借过等人挪开，或走侧面的缝；通过后继续原目的地 |
| 下扶梯的人站在出口看手机 | 出口被占住，刚上完又要停下来 | 请他让开或侧身绕行；画面能看到人挪到旁边 |
| 小孩横冲直撞 | 孩子在通道上横穿，接近时需要刹停 | 等他过去或避让，后面接着赶路 |
| 安检非常慢 | 选队以后，眼前的人逐个接受检查，暂时不能前进 | 看行李与队伍选队；可换队但重新排，轮到自己还要放包 |
| 人工窗口不开 | 跑到跟前才被关闭的设施拦下，等待不能让卷帘门自动打开 | 看旁边开放的自助通道，实际走过去；仍需正常检票 |

重复的是“急着走—眼前被挡—操作通过—又跑起来”的节奏，具体的人、位置、拥挤程度和可用空隙应有变化。小阻碍应短而频繁，必要设施可以占更长时间；不能每次都弹一大段文字，把连续赶路打散成问答。

判断是否做对，先看五件事：障碍能不能看见；是否真的挡住小人；操作能否改变人或路线；时间是否随处理自然经过；放行后是否接着赶原来的路。

## 人物差异应当直接落在选择和操作上

| 人物 | 玩家一开始就该懂的处境 | 真正不同的玩法 |
| --- | --- | --- |
| 背包大学生 | 在朋友家或咖啡店玩得舍不得走；高电量、高精力，总觉得来得及 | 管时间、背包位置、专注和冲刺；带蛋糕后占一只手、护着盒子更费体力；不带会伤心走神。不能出现属于自己的工作群或老板催促 |
| 打工人 | 妈妈舍不得放人，又不断塞东西；自己必须回去上班，老板还在烦 | 管负重、工作干扰和返工情绪；高专注有助判断；回复老板与承受来电风险形成不同取舍 |
| 疲惫游客 | 已退房、走了一整天，还必须回家上班；陌生地方处处碰壁 | 管低精力、疲劳、找路和补觉；不能只是大学生换个外观、把数值调低 |
| 带娃家长 | 不仅自己要到，孩子也要跟得上 | 管家长精力、孩子体力、耐心、尿意和距离；牵手、抱、等、安抚和厕所都有不同代价 |
| 出行家庭 | 婴儿车和全家同行让路线受到限制 | 无障碍、电梯、坡道、折叠推车与成员配合；目前仍是后续规划，不写成已经可玩 |

不同人物在同一站应有不同解法。大学生可能走楼梯，游客需要恢复，家庭必须考虑推车；不能只给同一组按钮乘不同的耗时系数。

## 选项设计的核心是取舍

我理解你这次指出的问题不只是“第一项总扣时间”，而是当前视觉和部分实际效果会让玩家形成“第一项吃亏，第二项直接走”的习惯。把顺序打乱并不能解决它。

每个选项都应回答四件事：**我做了什么；得到了什么；付出了什么；后果什么时候发生。** 不是每个选项都必须加一项惩罚：读懂线索并做对判断，本来就可以得到更好的结果。对有风险的选择，要说明风险类型，但不要提前泄露抽到的结果。

| 取舍类型 | 合理例子 | 应避免的问题 |
| --- | --- | --- |
| 时间换持续状态 | 吃饭会耽误出发，但后半程不因空腹降低精力上限 | 只写扣 60 秒，收益不明显或满状态时完全不生效 |
| 眼前进度换后续风险 | 先走，到检票时再找证件 | 用“不花时间”“无事发生”暗示没有后果 |
| 情绪与负担 | 带蛋糕提高专注，但增加负重、占手并消耗体力；不带会走神 | 拿着蛋糕就加体力，或只写剧情不影响任何东西 |
| 距离换稳定 | 外侧路远但少人，近路拥挤且可能需要处理障碍 | 两条按钮最后走同一路，只在结算扣不同秒数 |
| 当前资源换路线 | 大学生用体力上楼梯，低精力角色等电梯缓一缓 | 电梯、楼梯和扶梯只是名字不同 |
| 处理干扰换心理负担 | 答应老板今晚发，体力下降但暂时清静；不理可能接到电话 | 选完后没有对应状态，后续照样发生同一套事件 |

**早餐题的表达：**

- 买饭团：红色 `−60 秒`，同时显示绿色的实际精力上限增益；补一句“吃饱，后半程不会挨饿”。
- 直接走：把红色 `精力上限 −10` 放在前面；补一句“到候车大厅后生效，后半程更容易跑不动”。
- 这是一道“留住眼前时间，还是保住后程状态”的题，不应默认哪项总是正确。

**显示规则：**

- 已知代价前置并醒目标红，包括时间减少、精力下降、上限降低、专注下降、负重上升等。
- 已知收益以绿色显示。颜色按含义判断：`疲劳 −15` 是收益，`负重 +5` 是代价，不能按正负号机械着色。
- 延迟生效必须写出条件；可能发生的后果要保留“可能”。隐藏队伍速度、碰瓷结果等不能在选之前直接泄露。
- 随机概率只作内部调参，玩家不看百分比；用“可能坐过站”“可能来电”等情境表达风险，不泄露本局抽到的结果。
- 上限会截断的恢复量，显示本次实际能得到的量。满精力时不能仍承诺获得额外 10 点。
- 没有数值的意义也可以成立，例如记住证件位置、带上可用的零食、获得新的处理方式。但情感收益若只存在于台词里，就不能宣称它已形成玩法收益。
- 选项初始颜色相同，没有默认答案；顺序按情境安排，不固定“第一项扣时、第二项跳过”，也不在玩家阅读过程中换位置。

## 时间与难度的边界

时间损失有三种来源：行程本身、阅读与操作自然经过的时间、明确的选择或意外代价。结算要能分清，不能同一件事重复扣时。

当前实现中，站内移动按压缩时间推进，读题、处理事件和停下按正常时间流逝。这是实现口径，不应成为玩家必须计算的公式。后续调难度时，应把首次阅读、找按钮、辨认路牌的时间算进去。

- 第一关首次通关率约 75% 是你提出的调参目标，**目前没有足够真实试玩数据证明达到**。此前只有约 3–5 人、且普遍冲刺的反馈，不能据此给出准确概率。
- 你明确要求大学生一路无脑冲会失败。对应体验应是持续冲刺先有预警，再因岔气停步、浪费时间；分段使用才有价值。
- 随机可以带来难局，但不能让正确准备、正确路线和正常操作也常常无解。原稿的“可影响内容约 70%、不可控约 30%”是设计倾向，不等于每个事件独立按这个概率抽签。
- 地铁是否发生意外有单独的内部配置；不要与上面的整体可控性比例混为一谈，也不要把概率显示给玩家。最新报站题按“去门口：5 秒、5 体力；坐着等：5 秒、可能折返 50 秒”实现。
- 休息、绕路、提前准备是否值得，要受剩余时间、路线长度和人物状态影响。不能做成永远只选跳过，也不能做成所有准备都必须买。

## 手机操作和过程反馈

地图行进时，让玩家容易找到当前位置、眼前路口、目标检票口和冲刺状态。触发事件时，重点从地图切换到当前动作，底部固定操作面板可适当盖住地图。

普通赶路也需要操作和反应，不能让玩家只看小人自动走。底部放两个大按钮“按住赶路”“按住冲刺”，同时用更大的正面小人显示正在迈步、加速、流汗、弯腰喘气和停下恢复。体力低、游客疲劳高、大学生呼吸负荷快到顶时，表情和动作应更吃力，并直接提示松手喘气或改为慢走。松手、切换到事件、离开页面都要停止长按输入，处理完障碍后等玩家重新按住。

按钮需要适合手指操作；当前题的重要信息和可选动作应同时看得到。长按、连点、翻找和选择都要告诉玩家正在做什么、做到了哪一步、完成以后发生什么。按住放包时包要移动，刷卡后闸门要开；不能只让百分比增加，地图还是同一个静止画面。

上一题的结果、当前题的地点和接下来的目标必须区分清楚。角色不能在事件尚未解决时继续穿过去；也不能靠倒计时结束替玩家自动完成必须的动作。

## 结算与长期奖励

结算先让人明白“我这局是怎么回事”，再看明细。

1. 成功或失败，以及由真实行为决定的主称号。
2. 一句短总结、1–3 个标签、2–4 条最关键原因。
3. 本站学到的策略、已获得的成就、人物解锁提示。
4. 详细时间和损失拆解默认折叠，供想复盘的人展开。
5. 再玩一局与分享称号；别人打开分享链接可以玩游戏。

失败顶部按差距程度给有情绪的短句：差得多、还差一段、就差一点。不要直接写“估计还差 533 秒”一类内部计算；也不能明明主要被环境耽误，却笼统指责玩家一路犯错。精确估算保留在明细中，并标出估算性质。

买了东西、遭了意外、还绕了路却最终赶上，应有对应的逆风称号，并说明真正追回来的是路线、冲刺还是操作。称号不随机发。成就和人物解锁是累计记录，失败只影响本局及连胜；本地存档不会自动跨浏览器、设备或不同网址同步。

## 当前实现中需要正视的差距

| 项目 | 当前检查到的情况 | 对齐后的处理方向 |
| --- | --- | --- |
| 地图与事件 | 本轮增加路上的实际阻挡、局部绕行与保留目的地；较长任务仍主要按阶段顺序出现 | 以连续赶路为中心，继续调整人群密度与节奏，让人物事件更多依赖实际路线和状态 |
| 选项视觉 | 原先只突出负时间，资源损失藏在小字里 | 本轮已把明确的资源代价和收益一起前置；早餐补上延迟生效说明 |
| 大学生早餐 | 配置加 15，但初始上限 90、总上限 100，实际只加 10 | 本轮显示实际可增加的值，不改变现有数值规则 |
| 打工人吃饭 | 已改成上限 +10、体力 +10，满 60 也能变成 70；分段冲刺脚本里仍不足以抵回 60 秒 | 收益已生效，继续验证什么状态下值得停 |
| 游客咖啡与休息 | 已按上限显示实际恢复量；减疲劳生效，咖啡仍可能不如直接走 | 分清即时恢复和降低疲劳，继续验证耗时与收益 |
| 纪念品与土特产 | 增负重真实存在，部分正向价值主要靠情绪与成就表达 | 确认是允许为情感挑战主动负重，还是需要增加途中可用的价值 |
| 游客修箱轮 | 已实际减少负重 5，移除未说明的额外精力损失 | 文案与效果一致，继续观察路线价值 |
| 地方特色事件 | 固定特色已建立，但有些仍偏读题后扣时 | 让路线、动作、人物状态和后续事件发生实际变化 |
| 难度目标 | 有自动化通关与冲刺检查，缺少足够真人样本 | 统计首次游玩结果、失败位置、剩余时间与选择，不以脚本胜率代替人类胜率 |

选项展示修正之后，本轮已继续实现上述地图阻挡循环，并修复部分资源计算；**没有完成所有选项的取舍平衡，也没有完成精细人群模拟**。计算方式、实际结果和未解决的问题见[数值设计与验证](./我一定会赶上这趟车_数值设计与验证_V0.1.md)。首次通关率还需真实试玩验证。

## 建议先对齐的四个决定

1. **地图自由度。** 我倾向“能看懂整体关系的通道地图，点选移动、路口可分支”，而非摇杆自由探索的大地图。是否符合你想要的走地图体验？
2. **事件出现方式。** 最新已对齐的是“人和设施直接挡在路上，接近后操作通过，继续原目的地”。后续要细化的是哪些人可以提前看见、哪些横穿需要临时反应，以及每段该出现多密。
3. **情感选项的价值。** 带小蛋糕、土特产和纪念品，允许玩家为了情感、称号主动承担负担；还是每一项都必须有可兑现的途中收益？我倾向保留情感选择，但把真实收益与纯叙事说清楚。
4. **事件密度。** 我倾向保留少量必须完成的关口，让途中遭遇有变化、有空档；每站具体遇几件事，先通过一局完整体验再定，不统一堆到固定任务数量。

确认这些以后，再调整地图触发逻辑与选项收益，避免边写边把游戏往另一个方向改。
