# 带娃家长：可玩方案 V1

状态：待实现的玩法方案。依据[人物设计原稿](./我一定会赶上这趟车_人物设计_带娃家长与出行家庭_V1.md)整理；原稿保留不改。本文件定义第一版可玩的取舍、规则和验收标准，具体秒数需在试玩后调整。

## 一句话体验

家长自己认得路、也跑得动，但孩子会累、会停、会突然有需求。玩家赢在**提前准备、照顾孩子的节奏，以及最后两个人一起冲过终点**，而不是独自跑到检票口。

这一关继续沿用游戏的“两座随机车站中选一座”、地铁路线判断、站内左右避障与操作题。带娃家长是第四个可玩人物，建议在游客首次通关后解锁；不让玩家在大学生首关就面对三条新资源。家长外观在每局开始时从爸爸／妈妈中抽取，仅改变立绘和称呼，不改变数值与事件结果。界面统一称“带娃家长”，结算文案避免一律写成“妈妈”。

## 本局流程

| 阶段 | 玩家做什么 | 这一步为何有用 |
| --- | --- | --- |
| 出门前 | 决定先带孩子上厕所、是否带零食 | 用眼前时间换后续稳定性；两个决定都会被结算追溯 |
| 地铁 | 选路线、认方向、在正确站下车 | 继续保留原游戏的判断；换乘和等车影响孩子状态 |
| 地铁出口 | 开始牵手走，左右避障 | 第一次看见家长与孩子有不同步速度 |
| 站内 | 处理一次固定的本站特色问题，另有 1–2 次由孩子状态触发的停步 | 选择和操作会真正拦住前进，且准备能改变解法 |
| 最后两分钟 | 在合适时机使用一次“拉好手，跑！” | 短时间同步冲刺；不能抹掉先前走错路或没处理的阻挡 |
| 结算 | 说明最大耽误、最大追回，以及孩子最终状态 | 让玩家知道是路线、照顾节奏还是操作决定了输赢 |

一局最多给玩家两道出门准备题、既有路线题、一道本站固定题、两道孩子需求题。碰到路障仍要换道；不把赶路做成连续弹窗，也不让孩子随机不停打断玩家。孩子状态可能使同一事件有不同选项和成本，因此不是固定答案题。

## 家长与孩子的状态

家长基础属性按原稿起步：敏捷 60、精力 70、专注 85、负重 30。家长看牌和安检判断较稳；单独移动能力不能比游客还弱。正常牵手速度略低于大学生，冲刺速度由孩子能否跟上决定。抱起孩子后不再产生牵手距离，但家长更快消耗精力、移动稍慢。

孩子状态单独保存，不混入家长的精力条：

| 状态 | 初始建议 | 增减来源 | 触发的实际阻挡 |
| --- | --- | --- | --- |
| 体力 `childEnergy` | 65–75 | 走路缓降；长距离、楼梯、连续冲刺降得更多；休息或被抱恢复 | 低于 35 时明显落后；归零时停下说“我走不动了” |
| 耐心 `patience` | 70–80 | 排队、催促、尿急、连续冲刺下降；零食、水、安慰恢复 | 低于 25 时提出需求；归零时拒绝前进，必须安抚 |
| 尿意 `toilet` | 出门先去为 0，否则随机 25–55 | 地铁时间慢慢增长，站内增长稍快；喝水后也会增长 | 达到 80 提醒，达到 95 强制出现“现在要不要去”的选择；达到 100 发生意外，但仍允许赶车 |
| 牵手距离 `gap` | 0 | 普通走路会缩小；持续冲刺会拉大；等待、回头、抱起归零 | 超过可视安全距离时家长停在原地，不能继续推进 |

这些区间是**首轮调参目标**，不在设计稿里锁死逐秒公式。实现时孩子体力与牵手距离按站内实际前进距离及冲刺时长结算，尿意按经过的游戏时间结算；地铁旅程和选择扣掉的时间只计算一次。这样不会因为当前“跑动时 1 秒等于 4 秒游戏时间”的显示规则而重复惩罚孩子。

孩子状态不能靠掷骰子突然归零。每局抽取的初始尿意、站内意外和风险在创建本局时确定；出门准备与途中操作改变结果。状态到阈值前要有台词、颜色和小动作预警。

## 会真正停住玩家的操作

站内的孩子问题使用一个明确的阻挡状态：触发后角色和进度停止，计时继续；完成选项及必要操作后才放行。若玩家什么也不按，不能自动跳过。任何阻挡都至少保留一个无需消耗道具、能继续前进的解法，避免卡死。

| 情况 | 玩家操作 | 结果与取舍 |
| --- | --- | --- |
| 冲刺把孩子甩在后面 | 松开冲刺并按住“等孩子”约 2 秒，或选择抱起 | 等待保留家长体力；抱起省等待，但之后走得慢、精力耗得快 |
| 孩子走不动 | 继续牵着慢走、抱起、或休息 30 秒 | 慢走保住眼前时间但可能再次停步；休息恢复双方状态 |
| 孩子耐心归零 | 有零食可立即给；没有则按住安慰，或花时间休息 | 必须处理才能继续；不允许“无视孩子继续冲” |
| 孩子说要上厕所 | 去厕所花约 60–90 秒并归零尿意，或先继续赶路 | 继续走能省眼前时间，但尿意会更快升高；到 100 触发意外，不自动判输 |
| 商店／喝水需求 | 用随身水和零食快速处理、短暂停留，或解释后继续 | 快速拉走会消耗耐心；前面准备过才有便宜选项 |

“尿裤子”是一次有后果的状态变化：孩子速度和耐心下降，家长专注暂降；玩家可以先上车再处理，不出现羞辱孩子的画面或强制换衣任务。未带零食、没有水、错过厕所时，也始终可用安慰、等待或抱起继续游戏。

最后两分钟出现一次性按钮 **“拉好手，跑！”**。启动后短时间内两人同步，冲刺不会拉大 `gap`，耐心不会因冲刺下降；仍要左右避开路障，仍会受体力上限约束。按钮应由玩家决定时机，不能自动替玩家使用。

## 出门准备如何改变后半局

1. **先上厕所**：扣约 60 秒、尿意归零；不去则保住 60 秒，但带着本局已抽定的初始尿意出门。玩家能在卡片上看到“现在省 60 秒，后面有风险”，不能隐藏代价。
2. **带零食**：负重小幅上升，获得两次恢复耐心的机会；不带则轻装，后续只能安慰或现场购买。水壶第一版默认随身一份，喝完后再需要水时才出现“购买／安慰”的选择，避免第三道准备题拖长开场。

这两个准备选择不设绝对正确答案。离检票时间充裕时提前上厕所更稳；时间紧时省下 60 秒可能值得冒险。结算要写出“你出门前花了 60 秒，站内避免了一次更长的厕所绕行”或相反的事实，不凭选择名称发称号。

## 六站的家长解法

保留现有六站底图、固定站点性格和路线形状，在相同地图上让孩子状态改变最佳解；不另做六套换名的亲子地图。

| 车站 | 孩子带来的新压力 | 有意义的解法 |
| --- | --- | --- |
| 上海虹桥 | 长廊持续消耗孩子体力，商店近路又容易分心和拥堵 | 早些正常牵手走、避开商店高密度路障，最后留同步冲刺；体力不足时先短休息或抱起 |
| 北京南 | 安检队伍不仅花时间，也会消耗孩子耐心 | 观察处理速度，选实际更快的队；排队前用零食或安慰，不靠持续冲刺弥补错队 |
| 广州南 | 近路的人流会拉开牵手距离，外围连桥较稳但较长 | 结合孩子体力和耐心选路；稳定通路通常更适合牵手，有足够资源时也可挑战近路 |
| 杭州东 | 出发／到达岔口附近有商店吸引孩子，边照顾边认牌 | 先确认铁路出发方向，再处理孩子的请求；错误岔路造成的折返不能靠家长高专注自动抵消 |
| 武汉站 | 楼梯省时间却消耗孩子体力；电梯等待会消耗耐心 | 看当前孩子体力与家长精力：牵手楼梯、抱孩子上楼或等电梯都可能合理 |
| 郑州东 | 老乡搭话挡住编号牌，孩子也容易在对称大厅停下 | 尽快结束聊天，先核对 21A 再走；保持牵手距离，避免为了追错侧检票口把孩子甩下 |

每站固定一道站点决策，孩子需求从状态阈值和预先抽取的候选中进入。避免同一分钟连着触发“走不动＋尿急＋耐心归零”：同一时间只展示一个阻挡，处理后给予一小段前进缓冲；未处理的高优先级需求仍会回来。

## 手机上的信息与画面

- 常驻 HUD 只放倒计时、家长精力，以及一条**最紧急的孩子状态**（例如“孩子快跟不上了”）。点开孩子头像才显示体力、耐心、尿意三个小条和剩余零食；不要让数值挤掉左右换道与冲刺按钮。
- 跑道里同时看到家长与孩子，孩子跟随位置随 `gap` 变化。掉队时孩子停在原道喊“等等我”，家长也被停住；抱起后变为一人抱孩子的动作。
- 选择卡先写清代价：“现在 −60 秒／之后尿意归零”。红色、大字号显示失去的秒数，避免 `−1:00` 这种难扫读的格式。
- 孩子罢工、尿急等事件以简短台词和一个操作为主，不做长篇剧情，也不让玩家在手机首屏之外寻找继续按钮。
- 爸爸／妈妈外观只改变人物图和称呼；事件、判定与难度一致。

## 时间、结算与解锁

倒计时沿用“发车前 3 分钟停止检票”。带娃家长的初始预算必须按所选站的可行路线、步行距离和至少一次合理照顾孩子的时间重新计算，不能简单把大学生速度乘以 0.82。理想情况要有余量；准备完全不当、持续无脑冲刺或连续选错路线可以失败。建议试玩校准首玩通关率和剩余时间分布，不先承诺一个未经测试的百分比。

结算先给直接原因，随后才列详细数字。至少记录：`childEnergyMin`、`patienceMin`、`toiletVisits`、`wetPants`、`separationCount`、`carriedSeconds`、`snacksUsed`、`childDelaySeconds`、`syncSprintSavedSeconds`。每个额外时间损失写入现有日志／归因系统，防止“明明没有犯错却输了”或给出未发生的称号。

已有的“带娃也能赶车”“一个都没掉队”“厕所危机解除”等称号和成就要由这些真实字段驱动。原系统里 `mom`／`mother` 的内部 ID 可为存档兼容保留，但对玩家显示“带娃家长”；原有“首次以带娃妈妈成功”等文案需要改成中性表述。成功时不只奖励零失误：经历尿急或掉队后成功，也要明确指出哪次准备、安慰或最后冲刺救回了时间。

## 开发顺序与验收

1. 新建独立的家长／孩子状态与纯计算规则，不往打工人、游客的状态里塞孩子字段；先验证阈值、恢复、出门准备和时间只扣一次。
2. 接入人物解锁、出门两道准备题、人物立绘和手机 HUD，保持现有三个人物流程不变。
3. 接入站内牵手距离、抱起与阻挡操作；确保停步后必须处理、处理后可以继续，最差资源状态也不死锁。
4. 为六站接入固定决策与 1–2 个孩子需求事件，复用原地图与左右换道操作。
5. 接入最后同步冲刺、结算归因、称号和成就，再针对各站及风险选择调时间预算。

验收时至少完整玩通六站，并覆盖：持续冲刺导致掉队、提前上厕所与不去的差别、零食用尽后的解法、耐心归零、尿裤子后仍能继续、抱起孩子过武汉楼层、倒计时到零后的合理失败、没有孩子事件误套到前三个人物。每次失败结算都应能指出由玩家决定或可见状态造成的主要差距。
