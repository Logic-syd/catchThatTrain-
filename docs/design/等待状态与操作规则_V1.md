# 等待状态与操作规则 V1

修订日期：2026-10-11。适用于当前四个已开放人物的准备、乘车、站内事件和操作。承接[任务成本与收益规则 V1](./任务成本与收益规则_V1.md)、[准备收益与任务资源规则 V1](./准备收益与任务资源规则_V1.md)与[孩子游戏时间结算规则 V1](./孩子游戏时间结算规则_V1.md)。本页细化固定费用中的活动性质；旧记录中“固定等待不推进自然恢复”的概括，以本页为准。原始设计稿及历史审查正文保留。

## 1. 时间只扣一次，资源按活动结算

| 活动 | 被动资源使用的时间 | 边界 |
| --- | --- | --- |
| 停步、读题、处理静止事件、普通到站等候 | 实际经过的游戏秒；这些阶段每真实秒推进 1 游戏秒 | 与同样长的固定等待共用恢复和消耗规则 |
| 排队、电梯、等人处理、专门休息 | 选项中实际收取的等待游戏秒 | `seconds` 只收费一次，`waitSeconds` 标明其中的等待部分，不再追加费用 |
| 地铁实际乘车 | 本次地铁进度增量 × `route.minutes × 60` | 只按乘车份额恢复；路线价格中的进站和换乘步行不算坐车休息，截断到站后剩余真实等候时间仍正常结算 |
| 实际站内步行、冲刺 | 原有真实 `dt` | 移动、精力储备消费、轮子额外消耗、冲刺负荷和孩子掉队仍使用已有移动规则 |
| 固定折返、楼梯、搬物、修轮子、通道附加步行 | 不自动算作静止等待 | 只执行已声明的任务成本和资源效果，不能因为扣了时间就赠送站立恢复 |
| 换乘、坐反方向、折返恢复动画 | 不算被动休息 | `transfer`、`wrong`、`metro-recovery` 阶段仍推进倒计时，不凭动画时长赠送恢复 |

`waiting.ts` 的 `fixedWaitPlan` 明确识别已有任务；新增含等待的任务应提供 `waitSeconds`，混合通道同时提供 `fixedWalkSeconds`。`waitSeconds` 不得超过实际固定费用；没有声明或已有语义映射的操作费用不推断为等待。准备的已定额恢复不会因其固定费用再补一份自然恢复；准备读题本身仍按实际等待推进。

逐帧读题和超时额外处罚分别计资源：前者已结算的真实时间不再纳入后一段。事件超时导致的额外静止耽误按实际扣掉的秒数补算，不能重复使用整次 `TICK` 的总扣时。通用处罚、导航错误和路程费用不能只凭日志标题含“等待”推断活动。

## 2. 当前被动速率与资源边界

以下单位均为每等待游戏秒。保留本轮前的被动速率，将适用时间统一；各资源仍按自身上下限截断。

| 人物／资源 | 当前速率 |
| --- | --- |
| 大学生体力 | `5 × (0.65 + 精力上限 / 100 × 0.4667) × (1 − 负重 / 250)`；已有最后阶段恢复倍率为 1.25 |
| 打工人精力 | +3.5；上限 60 |
| 打工人疲劳 | −0.00025；最低 0 |
| 游客精力 | 基础 +2.5；疲劳达到 80 时乘 0.75，达到 60 时乘 0.85，更低时乘 1；上限 35 |
| 游客疲劳 | −0.00075；最低 0 |
| 家长精力 | +1.15；上限 70 |
| 孩子体力 | 未抱时 +0.02，抱着时 +0.22；上限 100 |
| 孩子耐心 | 站内 −0.055，其余被动阶段 −0.018；最低 0 |

大学生奶茶仍只覆盖进站后前 180 游戏秒的自然恢复，倍率 1.2。一次长等待跨越窗口时，只给剩余有效秒数加成；准备、乘车不能提前用掉站内窗口。游客一次长等待跨越疲劳 80／60 的边界时，按各段实际经过的时间积分，不能整段沿用起点或终点倍率，以保证拆成小步后结果相同。

孩子尿意继续读取整次动作实际扣除的游戏时间，速率与阶段沿用既有规则，不由被动恢复函数再算。等待函数不改变掉队距离、冲刺次数、同步窗口、缓冲时长、移动距离或抱娃移动累计。同步和缓冲仍按真实输入时间流逝，不能把地铁的压缩游戏秒灌入这些计时。

等待不消费精力储备，也不触发轮子额外消耗。游客疲劳、孩子耐心、精力与体力的新值继续进入后续移动倍率、耗尽解除和状态阻挡判断；恢复不提高资源上限，也不自动恢复冲刺。家长耐心和孩子体力最低值随实际变化更新。

## 3. 专门效果替代同一段等待的同字段变化

“已包含”的字段由任务语义确定，不能以本次数值是否刚好变化来判断。即使当前已满导致实际恢复为 0，该定额仍替代同一等待的自然恢复；不能换一条路径再拿到奖励。未被替代的资源继续按对应活动时间变化。

| 任务／选项 | 等待与定额处理 | 后续消费者 |
| --- | --- | --- |
| `security-queue`、`gates` | 排队部分按等待推进；大学生移除原有 `seconds / 4` 的第二套恢复 | 精力、孩子耐心和尿意影响后续赶路与阻挡 |
| `gz-lift/lift` | 45 秒等待；精力恢复最多 25 为此选项定额，替代精力自然恢复 | 人物自身精力上限、移动速度和冲刺资格 |
| 打工人／游客 `vertical-choice/lift` | 35 秒等待；精力最多 +15 为定额，疲劳仍自然变化 | 后续移动及恢复效率 |
| 大学生 `vertical-choice/lift` | 35 秒等待；体力走统一自然恢复，不额外叠旧电梯公式 | 体力和耗尽状态 |
| 家长 `vertical-choice/lift` | 38 秒等待；孩子体力 +12、耐心 −6 为此段定额，家长精力自然恢复 | 孩子疲惫、拒绝前进及家长冲刺 |
| 家长 `parent-tired/rest` | 30 秒；精力 +7、孩子体力 +36、耐心 +8 已包含本次休息，不另加同字段变化 | 解除疲惫或改变后续速度与阻挡 |
| 家长 `parent-patience/rest` | 25 秒；精力 +5、耐心 +32 为定额，孩子体力继续自然恢复 | 恢复前进资格和后续精力 |
| `parent-gap/wait` | 点击选择后扣 8 秒；孩子体力 +4 为定额，家长精力和耐心自然变化；成功完成才将距离归零 | 解除掉队阻挡，不虚记已前进距离 |
| `parent-patience/comfort`、零食 | 安慰 12 秒、零食 5 秒；耐心定额替代同段耐心变化，其他等待资源正常推进 | 无库存仍能安抚；消耗库存与实际使用次数各记一次 |
| `sh-parent-shop/water`、`buy` | 喝随身水 3 秒、购买 35 秒；耐心为任务定额，其他适用等待资源推进 | 水库存、耐心、负重与尿意各按自身边界结算 |
| `wh-parent-duck`、后续买食物／吃零食 | 购买或吃零食的固定时间按等待；耐心为定额 | 库存、耐心、是否跳过再次讨食任务 |
| `bj-parent-strict` | 分盘／重检固定时间按站内等候；重检耐心 −12 替代该段自然耐心变化 | 安检放行及孩子耐心 |
| `student-breath` | 固定恢复到至少 65、受当前上限约束；这份体力效果替代同段等待恢复 | 呼吸处理完成后继续前进，不重复回血 |

抱起孩子、走楼梯和杭州绕到远电梯等混合操作保留其明确费用与效果，不把整段固定成本视为静止恢复。游客补觉继续使用并行选择的单次精力／疲劳效果；正常乘车的被动资源独立来自实际乘车时间，不能再扣一份“补觉等待”。

以下补算及完成顺序必须保留：

- 准备 `parent-prep-toilet-first` 的 60 秒等待现在也推进家长精力、孩子体力和耐心；完成时尿意最后归零。站内 `parent-toilet/toilet` 同样归零在最后，耐心恢复按任务定额。
- `parent-accident` 完成时尿意设为 50，孩子体力和耐心扣耗为任务定额，不能在完成后的 50 上重新增加整段费用时间。
- 饮水额外尿意与时间自然增长各计一次，最终受 100 上限限制；库存只消费一次。
- 推人后实际触发碰瓷的 60 秒是等待处理，要补被动资源；结果卡显示“已扣 60 秒”，关闭结果不再收第二份费用。顺利通过的 2 秒不假装是同样的长等候。
- 达到孩子阻挡阈值后，使用统一结算完成后的状态判断；维持单个事件及既有处理缓冲，不能在同一动作反复弹出多个孩子任务。

动态卡片由同一等待计划生成，在明确任务效果之外显示“等待期间”的实际变化；满值不虚报收益。选择读取当前标准选项和费用，不信任过时卡片携带的价格。主动选择的资源日志记录动作前后实际状态，包含本次等待和任务效果；这些资源变化不再折成一笔时间费用。

## 4. 玩家操作与显示一一对应

| 操作 | 实际行为与文案约束 |
| --- | --- |
| 普通选择 | 点击一次提交。家长等孩子、安慰和休息保留可比较的多个选项，固定时间直接写明；不再写成玩家需要按住 |
| 按住 | 只累计输入确实按下的真实时间；松手暂停并保留进度。失焦、离开按住区域、指针取消、丢失捕获及页面隐藏会停止累计；事件完成只提交一次 |
| 连点 | 显示该事件的实际按钮名称和所需次数，不再统一写“跑！跑！跑！”。闹钟醒来是点击一次；扶梯快走、上楼和登车按各自次数完成 |
| 滑动 | 指针向上达到阈值完成；键盘聚焦后可按 Enter 或空格。取消或失焦会清理手势状态，文案公开真实替代操作 |
| 扫描／识别 | 点中指定物品或正确编号才放行；固定办理时间另行显示，不能把动画完成等同于免费通过 |

`eventTiming.ts` 的 `eventTimeLimit` 同时供界面和引擎读取。大学生沿用专注窗口 `0.7 + focus / 100 × 0.6`；打工人、游客和家长沿用固定事件窗口，不再由界面擅自缩放。找钱包／找证件分别使用 8／6 秒基础窗口；游客闹钟使用实际 3 秒窗口。

`eventHoldSeconds` 统一计算按住所需时长，大学生持奶茶沿用 1.25 倍。界面同时展示“累计按住 N 秒”和完成后另外收取的固定游戏秒；读题、按住或点击实际耗时始终正常计入倒计时。固定费用不是对同一输入时长再次收费，而是明确说明的办理／排队活动。

单次连点事件中的其他选项也能从界面选择，例如游客醒来事件的“再睡一下”。已关闭事件保留的退场画面不再接受输入，不能触发重复选择。

## 5. 通道、扶梯和提前靠门

`gates` 的稳定选项 ID 为 `lane-1` 至 `lane-8`。每项 `seconds = fixedWalkSeconds + waitSeconds`，详情完整显示附加步行、排队和合计。附加步行是公共站内路段之外的选中通道距离，合计只在选择时扣一次；被动资源只使用排队秒数。比较快慢和相关结算使用同一完整费用，不能只看人数或排队时间。

八条通道的队列时间在创建本局时随随机源确定并保存在 `stationLuck.gateQueues`。读题、动态刷新、打开地图和渲染不得再次抽取；没有该字段的旧状态使用确定性默认队列，不临时随机改价。

当前线性流程中，畅通扶梯的“快走”进入真实连点操作，通常 4 次，大学生持奶茶需多一次整理；不再宣称获得额外 4 秒移动加速。站稳／正常／拥堵路线分别有配置的固定等待及按住操作，两部分都公开。大学生扶梯环境费用继续受现有总额上限约束，卡片和被动恢复读取实际仍会收取的费用，达到上限后不按未收费的时间恢复。

`metro-crowded-door` 明确两种行为：`move-door` 花 12 秒绕过行李提前靠门，`wait` 花 40 秒等人群通过后靠门。完成后大学生 `doorReady=true`，最近一次对应下车不再重复收取未提前靠门的 12 秒；随后继续乘车、换乘等流程仍按原规则重置靠门状态。等待分支推进等待资源，绕走分支不能套同样的静止恢复。

## 6. 后续任务与验证要求

新增或修改任务必须写明：活动类型、固定总时间、其中等待与步行各多少、额外真实操作、哪些资源已包含在定额中、完成时的设置／恢复／库存效果，以及后续消费者。稳定任务和选项 ID 决定行为，不靠描述文本推断活动。动态卡片、标准选项、引擎费用、资源预览和日志必须使用同一计划。

针对性验证包括：相同时长固定与逐步等待、疲劳及奶茶窗口跨阈值、资源空值／满值、定额效果不重复、厕所最后归零、碰瓷实际费用、地铁乘车与步行份额、同步／移动计时不受固定等待污染，以及重复输入不再收费。操作验证需覆盖真实指针／键盘行为、按住松手与失焦、连点次数和替代选项，不能只直接调用 reducer。

本轮针对性测试入口包括 `parentWaiting.test.ts`、`characterWait.test.ts`、`eventTiming.test.ts`、`eventInteractionUI.test.tsx` 与 `gateCosts.test.ts`。共享引擎的完整回归、构建和真实初始预算流程遍历由本轮整体验收记录；此处不复用上一轮测试计数或模拟结果。

本轮验收：`npm test -- --reporter=dot --maxWorkers=2` 完整执行 30 个测试文件、434 项测试，全部通过；`npm run build` 通过。`waitingIntegration.test.ts` 覆盖固定／实际等待、自动超时的结算顺序、任务定额、资源日志、费用封顶及靠门后去重。Chromium 完成 9 项真实操作检查，覆盖按住、松手、延迟、失焦、卸载、批量连点、醒来替代选项与失效事件输入，没有页面异常；这不是全人物手动通关验证。浏览器脚本与报告在 `/workspace/scratch/ui-interaction-*`。

真实预算遍历仍采用原来的四人物、六站、两难度、三策略，共 144 局：81 成功、63 次检票截止失败，全部正常结算，无卡死和资源越界。174,192 次状态转换包含 274 个选项分支探针，家长恢复仍封顶 70/70；通道和预测重复读取 10 次保持不变。家长 24 秒排队快照中，精力 40→67.6、孩子体力 50→50.48、耐心 70→68.68、尿意 20→22.4，卡片与日志相符。结果在 `/workspace/scratch/waiting-audit-results.txt`。

相对上一轮固定策略的 90 成功／54 失败，本轮有 9 局由成功变为截止失败，新增截止位置均在通道选择或刷证处。原预算和审计策略未放宽；本轮同时改变通道完整收费、队列抽样和等待规则，随机源消费也有变化，不能把这 9 局单独归因于一个参数。该结果是策略样本的版本对比，不是真人胜率，后续难度校准应保留这份证据。

## 7. 采用范围与保留差异

本轮统一的是当前已实现活动的时钟、资源与操作承诺，并未采用原始人物稿中的全部设想。例如孩子坐地铁恢复耐心、长时间站立消耗孩子体力，本轮没有新增：当前乘车仍按站外速率缓慢降低耐心，未抱孩子的普通等待仍缓慢恢复体力。它们是明确保留的当前参数，不能宣称已经完全符合原稿。

不因此宣布静态最优标签、所有人物平衡或未接入的旧任务全部完成。长期等待现在确实会改变资源，可能影响既有策略；后续应依据真实预算与玩法验证调整数值，不通过重置资源、增加隐藏时间或重复恢复掩盖问题。原有移动、冲刺、尿急禁冲刺及一次性任务效果的回归仍是必要条件。
