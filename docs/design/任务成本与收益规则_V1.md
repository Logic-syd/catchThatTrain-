# 任务成本与收益规则 V1

状态：后续任务设计、实现和评审的约束。适用于四个已开放人物的准备、地铁、站内事件和主动操作；未来新增人物同样适用。现有不符合项见[当前任务审查](./当前任务成本收益审查_2026-10-10.md)。本规则不代表现有问题已经修复。

原始设计稿保留不改。本文件承接整体玩法的可控性原则、人物差异、家长时间只计算一次，以及结算 V1.1 的真实归因要求；具体秒数仍需模拟和试玩校准。

## 1. 先说明任务类型，再判断收益

| 类型 | 合理的收益 | 必须满足 |
| --- | --- | --- |
| 资源交换 | 恢复资源、改变能力、获得库存、降低后续消耗 | 常见可达状态中存在有意义的使用场景；不能长期只付成本 |
| 准备／风险管理 | 已知位置、获取信息、减少或消除后续风险、获得新解法 | 对应的后续判断或操作实际读取该状态 |
| 路线策略 | 更短路程、更低障碍密度、省换层、保留资源 | 存在可解释的适用条件；风险高不等于本局做错 |
| 识别判断 | 选对入口、楼层、队伍、编号 | 可以有明确正确答案；错误后果来自玩家可见的信息和真实选择 |
| 强制操作／障碍 | 解开阻挡、通过安检、完成检票和登车 | 不需要附送属性奖励；成功处理确实放行，未处理不能跳过 |
| 剧情／收藏 | 故事、称号资格、收藏或情感表达 | 明确标为此类；不能伪装成赶车增益，不能把选择旗标当实际收益 |

不要求每个选项都比替代选项更强，也不要求每次选择都节省时间。允许明显错误答案、主动冒险和纯剧情选择。需要修复的是承诺无法兑现、状态没有消费者、信息不足的假取舍，以及没有标明的无效付费资源选择。

2026-10-11按用户最新设计，大学生的摸猫／围观／扶奶奶／茶颜悦色可显示幸福感或道德+20，让正面剧情诱惑与赶车时间形成取舍。这些积分必须记录并在状态栏／结算兑现，但不进入赶车属性或正的时间收益；不能冒充精力恢复、速度或准备奶茶增益。具体成本、活动类型和后续修改约束见[人物难点与事件规则 V2](./人物难点与事件规则_V2.md)。

## 2. 当前值、上限和增益分开

必须区分 `currentEnergy`（当前精力）、`maxEnergy`（上限）、`initialEnergy`（初始值）及临时增益。不同人物可以有不同上限；初始值不必等于上限。资源范围、单位和消费者必须明确。

- **恢复**：`实际恢复 = min(标称恢复, max(0, 上限 − 当前值))`。例如 58/60 恢复 10，实际只恢复 2；60/60 实际恢复 0。不得为了保证“+10”而偷偷扩上限。
- **提高上限**：明确写“精力上限 +N”，并说明是否同时补当前值、是否仅本局有效；不能与恢复混用。
- **临时增益**：明确倍率、开始时点、使用场景、持续时间所用时钟、结束和叠加规则。
- **资源消耗／减少**：同样按实际边界显示。例如疲劳 5 降低 15，实际降低 5；已满耐心不能显示恢复了固定 30。
- 多个准备按实际顺序计算，后一道卡片必须读取前一道造成的状态。不能在不相关选择中重置当前精力到上限。

资源类卡片应显示当前状态下的实际变化；必要时同时显示标称能力，例如“最多恢复 10，当前可恢复 2”。满值且没有其他实际作用时，标明“当前已满，无恢复收益”，可禁用该资源选项；如果保留为剧情选择，明确剧情目的。库存型准备要说明收益是获得几次后续使用机会，而不是已经恢复了资源。

**开局例外不得成为常态**：准备题若在默认开局必然满值，不能靠所有玩家都看见“无收益”维持题目。应重设计为可兑现的储备、饱腹／防止后续饥饿、明确的能力增益，或重新设计初始值与上限。改变容量或初始资源必须复验移动、恢复、冲刺和时间预算；不能只提高上限就宣布平衡完成。

## 3. 收益必须走完整个链路

每个承诺都要能指出：**选择 → 状态变化 → 后续规则读取 → 玩家可观察结果 → 结算事实**。

例如检查身份证的收益是记住前袋并缩短取证操作，不是凭名字记“省了 28 秒”。带零食的收益是后续解法，不是仅设置 `snacks = 2`。修轮子必须改变后续轮子阻力或消耗，不能用未显示的其他资源变化冒充修理。

新任务的收益必须在当前可达流程内有机会使用；只在未上线任务中才有消费者的属性，不算当前玩法收益。对已经被前一道任务解决的问题，不重复收取相同解决费用。

## 4. 时间、恢复与增益只结算一次

明确区分路程／等待的游戏时间、读题／按住／点击的真实操作时间，以及事故造成的额外时间。选择卡给出的固定秒数须说明是否另有操作时间，不能用“约 8 秒”掩盖自动重复扣时。

- 地铁中睡觉或其他并行行为占用已经计算的行程；额外扣时必须有额外等待或坐过站等依据。
- 瞬时扣掉的排队、等待、照顾孩子时间，也要按对应活动推进相关资源状态；恢复不能一边按等待给定值、一边又按同一等待逐秒重复恢复。
- 增益必须覆盖实际使用窗口。准备阶段得到的“前 3 分钟站内恢复加成”不能在尚未到站时全部过期。若设计为从购买起计时，必须明确说明并验证该窗口确实有用。
- 上一步的站内统一小步推进继续适用。新增任务必须验证大步延迟与相同小步序列下的时间、资源、阻挡和账本一致。

## 5. 取舍用实际策略评价

资源或路线交换至少说明一个可达的适用状态和一个不适用状态，例如精力不足适合电梯、时间紧且体力足适合楼梯。阈值由后续需求和实际效果决定，不只看静态“精力高／低”。

不把所有收益强行折成固定秒数。信息、风险、库存和剧情可以独立记录。可以用同起点、同随机种子、同操作策略比较整段耗时；不能把路线“稳妥”标签当实际更快的证据。风险选择的失败不等于随机事件在替玩家作决定；已知的错误入口等判断题可以明确标错。

## 6. 卡片、实现、操作和结算一致

- 详情中的每个数值和持续后果都必须由实现兑现；未实现的规划从当前卡片移除，不能保留承诺。
- “按住”“连点”“等孩子”等文案必须对应真实操作组件及完成条件。引擎能接收某个选项，不代表玩家在界面上能选择它。
- 固定成本、动态收益和适用条件应来自同一份规则或纯计算结果，避免组件与 reducer 各写一套数值。
- 新任务使用稳定任务 ID／选项 ID；不要再靠显示文案匹配行为。修改文案不应改变效果；旧任务的迁移保持存档和事件日志兼容。
- 应记录标称／实际资源变化、上限变化、库存使用、增益生效与失效、触发／跳过的后续任务，以及实际时间支出。未使用库存、未触发风险不能被结算推断为节省了固定秒数。
- `TimeImpact` 是有基准的比较影响，不与总耗时重复相加；同一损失只记一次。估算标“约”，没有证据的关键败因和成就不能补猜。

## 7. 新增或修改任务的交付模板

每次任务变更，在设计记录或 PR 中补全：

1. 任务／选项 ID、人物、车站、阶段及触发条件。
2. 任务类型与要制造的选择，适用／不适用状态。
3. 时间、资源和库存成本；基于当前状态的实际收益与边界。
4. 生效字段、后续消费者、作用时长、叠加／重复处理规则。
5. 可观察反馈、退出或无道具解法、时间账本和结算依据。
6. 与前后任务的组合、涉及的初始预算，以及下面的验证结果。

收益链路或必要触发条件缺失时，不能把任务描述为已完成。

## 8. 验证要求

按变更风险选择验证，至少覆盖受影响的承诺；不要只断言“扣了 60 秒、设置了旗标”。

- 资源：空值、正常值、接近上限、满值；核对详情与实际增量，上限是否被误改。
- 顺序：准备组合的两个顺序（若允许）、前一题已恢复／增益后的下一题；验证没有无关满血重置。
- 后续效果：至少一个有实际收益的可达状态和一个不适用状态；确认后续消费者，临时增益在需要时仍有效。
- 状态与库存：重复动作不会重复奖励；道具用尽仍能继续；恢复后确实解除或改变阻挡。
- 时间：路程、固定等待和实际操作不重复记账；延迟计时不丢移动；结算记录是实际发生值。
- 交互：新操作或修改操作至少验证玩家能从界面完成；不能用直接 dispatch 代替界面可达性验证。
- 流程：跑受影响人物／车站／难度的真实初始预算，保留准备和操作成本。完整流程失败要诊断，不能任意增加剩余时间使测试通过。

涉及共享规则时执行 `npm test` 和 `npm run build`；只有文档修改时检查链接、规则与代码证据即可。模拟样本必须说明策略与覆盖范围，不得称为真人首玩通关率。
