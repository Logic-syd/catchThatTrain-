# 我一定会赶上这趟车：选项价值与容错分析 V1

日期：2026 年 10 月 9 日

分析基线：`81f1c20`（冲刺收益校准后）。本轮只增加分析脚本、测试和报告，游戏参数不变。

## 1. 结论与优先顺序

当前不宜继续缩减 240／180／135／90 秒人物容错。先解决两件事：**读题稍慢会触发额外大额罚时；部分准备付出时间，却没有得到足够的实际收益。** 前者让玩家因阅读速度而失败，后者鼓励熟悉规则的玩家跳过准备。两种现象可以同时存在，不能用一个总通过率掩盖。

建议顺序：

1. 分清自然读题耗时、真实操作失败和固定罚时，消除不必要的叠加及人物计时差异。
2. 校准早餐、咖啡、证件整理等准备的收益，让不同资源状态下出现不同的合理选择。
3. 再检查路线取舍和人物剧情，保留可读懂的误导，不用城市常识或隐藏参数替玩家判断。
4. 最后重新测正常完成耗时，加回既定人物容错，再做混合行为及真人首局测试。

这里的调整都是下一步建议，尚未实施。开局时间、冲刺参数、人物容错和线上版本均未因本报告改变。

## 2. 测量方式与边界

四人物、六车站，普通模式。主分析每组 8 个固定种子（921 起，每次加 83）：

| 分析 | 范围 | 引擎运行次数 |
| --- | --- | ---: |
| 准备、路线、读题与方向错误 | 26 种准备组合、18 组路线／剧情对比、120 组敏感性场景，共 294 组 | 4,704 |
| 更频繁的分段冲刺 | 9 种准备组合 × 6 站，共 54 组 | 864 |
| 读题罚时来源核查 | 四人物六站，各比较 5 秒／8 秒，单一种子 921 | 48 |
| 合计 | 完整用时与真实截止时间分开测量 | 5,616 |

每组比较两类结果：延长截止时间，测完完整路线，防止把半途失败误算成更快；另用真实开局判断能否完成。表中的“多／少花时间”均是相对同人物、同车站、同种子参考流程的完整检票前耗时差，包含后续影响，不只是按钮上显示的扣时。正数更慢、负数更快。

参考流程沿用每个新提示读题 5 秒、连续操作后续提示 0.75 秒，以及大学生／打工人／游客／家长 15%／10%／6%／8% 的参考冲刺占比。压力组改用已有“冲 4 秒、走 3 秒”的策略，仍受体力、冲刺负荷及孩子距离约束；它不是所有人物的最优玩法。

参考准备为：大学生不带蛋糕、整理证件、吃早餐；打工人带特产、吃饭、回复老板；游客喝咖啡、保留行李；家长先上厕所、带零食。因此分析不是把参考准备预先认定成最划算的选择，恰好是在检查它是否合理。

**这些是固定策略的工程比较，不是真人通过率。** 8／8 只能表示该场景的八次完成。脚本读题、找证件、看路牌和处理阻挡都比真实新玩家稳定。同一种子在分支改变随机数消耗后，也不保证后续事件完全一致。压力组资源按模拟状态回调采样，不是对所有瞬间资源状态的数学证明。

本轮只覆盖普通模式及列出的准备／路线策略，未穷举全部地图分支、极限模式、触屏误操作，也未建成原稿的四类行为大样本模型。

## 3. 首要问题：读题成本存在突增

每题从 5 秒改为 8 秒，除了多用的自然时间，打工人、游客、家长还会触发额外操作超时罚时。大学生同类超时目前主要标记状态，没有同样的固定超时扣款。

上海、种子 921，后三个人物都多触发以下 140 秒：

| 来源 | 额外固定罚时 |
| --- | ---: |
| 背包挂住 | 25 秒 |
| 绕过老人后的操作 | 15 秒 |
| 扶梯操作 | 15 秒 |
| 行李箱操作 | 35 秒 |
| 找身份证 | 35 秒 |
| 检票扫描 | 15 秒 |
| 合计 | **140 秒** |

这个例子中打工人完整用时总共增加约 206 秒，其中 140 秒来自上表，而不只是多读了几秒。代码来源为 `engine.ts` 的站内 `eventOverdue` 分支：自然倒计时继续走，超时再扣一次固定 penalty；大学生走单独分支。统一角色折返倍率虽已撤掉，这处差异仍存在。

八种子、真实开局，读题 8 秒的完成数：

| 车站 | 大学生 | 打工人 | 游客 | 家长 |
| --- | ---: | ---: | ---: | ---: |
| 上海虹桥 | 8／8 | 2／8 | 0／8 | 0／8 |
| 北京南 | 8／8 | 8／8 | 8／8 | 0／8 |
| 广州南 | 8／8 | 8／8 | 0／8 | 0／8 |
| 杭州东 | 8／8 | 8／8 | 8／8 | 6／8 |
| 武汉 | 8／8 | 8／8 | 8／8 | 0／8 |
| 郑州东 | 8／8 | 8／8 | 8／8 | 0／8 |

家长确实应更难，但难点应主要来自孩子、负重、操作和 90 秒容错。不能把认真读提示普遍当成额外操作失败。建议先统一普通读题／操作等待的计时口径，保留有明确失败动作和可感知后果的惩罚。必要操作有时限时，要把读题与实际操作窗口分清，避免读完已经超时。

## 4. 准备选项：时间投入没有充分兑现

下表是各站“八种子平均差值”的最小到最大范围，不是单局极值。其余准备与参考流程保持一致。

| 改变的选择 | 完整用时变化 | 当前体现 |
| --- | ---: | --- |
| 大学生不吃早餐 | 六站均 −60 秒 | 上限损失存在，但参考节奏下没有转化为赶路代价 |
| 大学生不整理证件 | 约 −19.5～−19.4 秒 | 后面翻找的成本不足以抵消提前整理的 30 秒，熟练脚本尤其明显 |
| 大学生带蛋糕 | +89.3～+94.4 秒 | 75 秒准备之外，拎着和保护也确实增加后续成本 |
| 打工人不吃饭 | −60.0～−58.9 秒 | 上限收益通常用不上 |
| 打工人留下特产 | −49.8～−34.2 秒 | 轻装收益明确，但带走的机械收益不足 |
| 游客不喝咖啡直接走 | −34.1～−28.0 秒 | 咖啡有后续帮助，尚不值当前时间投入 |
| 游客休息片刻替代咖啡 | −9.2～−5.6 秒 | 同样比喝咖啡更快 |
| 游客减轻行李 | −39.2～−25.7 秒 | 轻装在本组条件下持续占优 |
| 家长不带零食 | −10.0～−0.1 秒 | 差距较小，接近有取舍的状态 |

26 种准备组合共 1,248 次真实截止测试全部完成，意味着参考玩家的正确路线可以承受这些准备差异，并不说明真实玩家都容易过关。

为排除“只是冲刺太少，所以体力无用”，补测更频繁的分段冲刺：

- 大学生不吃早餐仍省约 59.7～60 秒；打工人不吃饭仍省约 51.5～61.4 秒。
- 游客不喝咖啡仍省约 25.4～34.9 秒。
- 家长不带零食在武汉变为慢约 0.3 秒，其他五站仍快约 6.1～9.7 秒。说明照顾孩子的收益已有一定场景差异。

这组策略未观察到上述准备变体体力耗尽，单纯提高体力上限难以让资源投资有意义。下一步应测“恢复效率、持续疲惫、后续可用操作”等能在正常路线兑现的收益，或降低过高的准备成本，不应仅为了让不吃饭输而追加一笔隐蔽大额罚时。

蛋糕继续保留占手、负重、保护消耗，也不恢复“带上加体力”。它可以有专注、人物情绪和后续剧情价值；是否要做到纯速度上也值得，需与情感选择的定位一起判断，不能假装目前是等价的竞速方案。

家长厕所已经能体现站点差异：不提前去，在上海／广州／武汉分别慢约 20.5／15.9／20.4 秒，在北京／杭州快约 29.9／39.9 秒，在郑州接近持平。这类延迟影响比“每题第一个扣时间”更接近预期；仍需检查玩家能否根据当前孩子状态判断。

## 5. 路线与人物事件：区分取舍和明确的错误

| 场景 | 当前比较结果 | 需要核对的设计 |
| --- | --- | --- |
| 上海：商店近路 vs 沿墙外侧 | 商店近路四人物平均快约 9.9～28.3 秒 | 外侧的操作更稳是否能在真实拥堵／误操作中兑现；本脚本稳定处理障碍，不能证明近路对所有玩家都优越 |
| 广州：中央路线 vs 外围连桥 | 中央路线四人物平均慢约 40.2／47.0／51.0／85.5 秒 | 提示中的近路收益与后续换层成本是否匹配；家长一次选择几乎吃掉整份 90 秒容错 |
| 郑州打工人：说真话 vs 报低工资 | 两者都比“不告诉”快 25 秒；真话专注 −10，报低专注 −5 并获体力收益 | 当前报低在这次对话的数值上占优；如保留两个答案，要有清楚的剧情定位或不同后续影响 |
| 游客：修轮子 vs 硬拖 | 上海／广州硬拖平均快约 13.8／14.9 秒 | 修理投入没有充分被后续效率抵消，需按剩余路程校准 |
| 游客：撑着不睡 vs 设好提醒睡 | 不睡六站平均慢约 10.9～18.1 秒 | 本脚本会准确叫醒，尚未计入真人判断／响应风险，不能直接判定不睡无价值 |

不是所有选项都必须一样快。看错“到达／出发”方向可以是明确失误，但前面必须有足够线索；资源交换应在不同状态下各有价值；剧情选择可以带情绪、后续事件或称号价值。这三类要分开设计。

隐藏随机概率继续只留在计算中，不向玩家展示百分比，也不在选项里提前剧透一定发生的后果。

## 6. 容错与环境检查的限制

方向错误脚本请求 1／2／3 次，不等于实际发生那么多次。上海、北京、广州、武汉当前可注入的目标事件最多实际发生 1 次，杭州最多 2 次，郑州可以发生 3 次。报告同时记录 requested 和 actual，不能据此宣称“所有站连错三次仍能过”。

同类方向失误的固定成本已不再按人物乘倍率。当前单次方向错误额外完整耗时多为约 55 秒，杭州首错约 45 秒。郑州三次错误约多花 126.5 秒，在该场景大学生、打工人、游客均为 8／8，家长 0／8；这能体现容错梯度，但不是全部错误类型的平衡结论。

复核上一轮 768 次参考流程的环境处理账目：各站人物的均值约 5.8～56.5 秒；上海家长单局最高约 69.4 秒，比其均值约多 28.2 秒，相当于家长容错的约 31%。当前开局已包含对应站点人物的参考均值，不能再加一次统一 35 秒。

这里沿用“参考环境处理”分类，包含部分可选择的处理成本，例如游客修轮子；它还不是原稿定义的纯不可控损失。样本未超过 75 秒，不等于已经实现随机损失上限。拆清不可避免等待、玩家应对、操作失败后，才能校准环境预期和上限；本轮不据这份混合账目直接改环境参数。

## 7. 下一步修改与验收建议

第一批只处理计时口径和准备收益，避免同时改容错、冲刺、所有路线，失去因果依据。

| 修改方向 | 验收标准 |
| --- | --- |
| 普通读题与真实操作失败分开 | 读题从 5 秒变 8 秒时，能解释每笔额外时间；普通读题不凭空增加一组人物专属固定罚时 |
| 早餐／咖啡／证件整理 | 在资源、路程、专注不同的声明场景中，至少能找到双方各自合理的情形；收益落到实际跑完所需时间与操作上 |
| 蛋糕与特产等情感选择 | 明确它是资源交换还是剧情选择，保留已经约定的人物叙事，不硬塞统一“奖励体力” |
| 重测正常完成用时 | 正常地铁＋赶路＋必要操作＋预计环境＋240／180／135／90 秒；不将机制调整偷偷变成减容错 |
| 后续路线与环境 | 在资源收益稳定后逐站测近路、绕路、安检和设施，保留车站差异及可理解的误导 |

后续再补不同读题速度、资源状态、具体操作失误的组合，以及真人首局样本。大学生约 75% 首次通过率仍是待验证目标，本报告不以固定脚本完成率替代它。
