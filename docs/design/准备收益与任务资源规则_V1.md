# 准备收益与任务资源规则 V1

修订日期：2026-10-11。适用于当前已开放的大学生、打工人、游客和家长，承接[任务成本与收益规则 V1](./任务成本与收益规则_V1.md)。本轮补齐准备收益、轮子与换层任务效果、资源上限及实际记录；原设计稿和[2026-10-10 审查快照](./当前任务成本收益审查_2026-10-10.md)保留，以本页和该审查末尾的修订说明更新处理状态。

## 1. 当前值、容量和储备各算各的

| 资源 | 边界与结算 |
| --- | --- |
| 大学生当前体力 `stamina` | 0 至当前 `stats.energy`；准备只补新增容量，不把原有缺口一并回满 |
| 大学生本局精力上限 `stats.energy` | 初始 90，准备提升后最高 100；未吃早餐进入候车大厅后下降 10，一局只触发一次 |
| 打工人／游客当前精力 | 0 至自身 `maxEnergy`，当前分别为 60／35；恢复不提高上限 |
| 打工人／游客精力储备 `energyReserve` | 独立库存，0 至 10；实际站内移动时自动补当前精力缺口，精力仍不超过自身上限 |
| 家长当前精力 | 0 至自身 `maxEnergy`，当前为 70；所有任务恢复和扣耗都经过该上限 |
| 专注、疲劳、孩子体力、耐心、尿意 | 各自限制在 0 至 100；卡片展示实际增减，不展示被上下限截去的部分 |

所有恢复遵循 `实际恢复 = min(标称恢复, 上限 − 当前值)`，消耗也不低于零。打工人／游客耗尽阈值沿用精力不高于 0.01、恢复至 10 解除；家长沿用精力为零耗尽、恢复至 12 解除。任务即时恢复或扣耗后就更新该状态，中间区间保留旧状态；解除耗尽不自动恢复冲刺。

## 2. 大学生：容量、饱腹和恢复窗口

这些是六站共用的出门准备，按奶茶、身份证、饭团的顺序各选一次。成本为选择固定扣除的游戏秒数，读题和操作仍消耗实际经过的时间。

| 任务／选项 ID | 固定成本与实际效果 | 后续消费者与适用边界 |
| --- | --- | --- |
| `tea` / `buy` | 45 秒；敏捷最多 +5，精力上限最多 +10，两项属性均封顶 100；当前体力只增加本次新增容量 | 敏捷进入移动公式；站内自然恢复获得限定窗口加成；持杯继续影响翻包和部分双手操作。缺时间时可选 `skip` |
| `id` / `check` | 10 秒；专注最多 +10；记住身份证在前袋 | 取证时无需猜夹层，使用已检查的取证时长；即使专注已满，信息收益仍有效。不恢复当前体力 |
| `breakfast` / `eat` | 25 秒；精力上限最多 +15，封顶 100；当前体力只增加新增容量；获得饱腹状态 | `breakfast` 阻止进入站内候车大厅阶段（`stage >= 3`）后的饥饿上限 −10。已经满上限时仍有饱腹用途，可选 `skip` 保留时间 |

默认 90 上限吃饭团实际提高 10，卡片显示 90 → 100；先买奶茶再吃饭团时，卡片显示上限 +0、当前体力 +0，并继续说明饱腹。检查身份证、跳过准备等无关动作不会把体力补满；例如先前体力 25，奶茶新增容量 10 后只有 35，检查身份证后仍为 35。

奶茶的自然恢复倍率为 1.2，从进入站内开始，覆盖前 180 **游戏秒**。`stationElapsedGame` 读取站内每次实际扣除的游戏时间，既包括移动、读题，也包括站内选择和处罚的固定时间；出门、地铁和换乘不提前消耗窗口。达到 180 后不再加成。它只乘现有自然恢复，不给固定等待再补一份恢复；丢掉杯子解除占手，已购买的恢复窗口继续按原期限推进。

## 3. 打工人和游客：恢复余量转为可消费储备

| 人物／准备选项 | 固定成本 | 标称能力及其他效果 |
| --- | --- | --- |
| 打工人第二道准备 `eat` | 60 秒 | 精力收益总额 10；先即时恢复，剩余转储备；`motherStayed=true` 记录实际留下吃饭 |
| 游客第一道准备 `coffee` | 50 秒 | 同上；疲劳最多 −15，最低为 0，记录喝咖啡 |
| 游客第一道准备 `rest` | 30 秒 | 同上；疲劳最多 −5，最低为 0 |

三项统一计算：

```text
即时恢复 = min(10, maxEnergy − energy)
新增储备 = min(10 − 即时恢复, 10 − 已有储备)
```

例如打工人 60/60 吃饭得到 10 储备，58/60 得到即时恢复 2、储备 8，20/60 得到即时恢复 10、储备 0。已有储备接近上限时只增加剩余空间，丢弃的溢出不会伪装成收益；卡片显示当前精力已满、实际恢复和实际储备增量。直接出发仍可保留准备费用，不会强制购买储备。

`tickCharacterResources` 在实际站内移动的同一个时间片先结算自然恢复／冲刺／轮子消耗，再用储备填补精力缺口。消耗量同时从 `energyReserve` 扣除、加到 `energyReserveUsed`；当前精力不突破 `maxEnergy`。读题、碰撞阻挡、停步、地铁与固定等待不消费储备。储备持续到本局结束，未使用部分只记录剩余库存，不换算成已追回时间；默认满精力准备因此仍有后续冲刺或耗能时可兑现的用途。

打工人 `reply` 花 20 秒、专注最多 +5并取消后续追问；`ignore` 不收固定费用、专注最多 −3，设置待触发来电 `bossCallsLeft=2`。`bossCalls` 初始为 0，只在实际处理来电时增加；不能把待发生的两次电话提前计为发生次数。来电 `worker-boss-call` 的 `answer` 花 35 秒、专注最多 +5并停止后续来电，`ignore` 继续保留剩余追问。专注增减按当前边界显示。

土特产 `take-gifts` 和纪念品 `keep` 明确为剧情收藏，负重分别最多 +15／+5；轻装选项显示实际负重变化。收藏不承诺资源恢复或固定省时。检查准备顺序时保留前一步当前精力、储备与疲劳，不以无关选项重置资源。

### 3.1 游客移动与恢复修订（本轮难度校准）

本次调整减轻冲刺之后低精力对持续步行的拖累，让短时冲刺和恢复节奏有实际位移收益。游客仍保留精力上限低、疲劳降低恢复的差异，不通过增加容量或隐含补时兑现收益。下表替代早期“保留原恢复率”对游客移动参数的描述；其他人物的移动参数不随本次游客修订改变。

| 项目 | 当前规则与时间单位 |
| --- | --- |
| 精力对移动速度的倍率 | `0.92 + 0.08 × (energy / maxEnergy)`，仅游客使用；满精力为 1，精力减少最多降低这一项倍率 8% |
| 普通步行恢复 | 实际站内移动每 1 **真实秒**恢复 `0.9 × 疲劳恢复倍率` 精力，按 35 上限截断 |
| 冲刺 | 相对当前普通步行速度乘 1.55，实际冲刺每 1 **真实秒**消耗 6 精力；疲劳不会打折这份消耗 |
| 被动等待恢复 | 每 1 **等待游戏秒**恢复 `2.5 × 疲劳恢复倍率` 精力，继续遵循统一等待分类及定额字段替代规则 |
| 疲劳恢复倍率 | 疲劳低于 60 为 1，达到 60 为 0.85，达到 80 为 0.75；只乘正向自然恢复，不乘冲刺或轮子扣耗，也不削减任务明示的定额恢复 |
| 上限与耗尽 | `maxEnergy=35`，储备上限 10；精力不高于 0.01 时耗尽，恢复至 10 才解除，解除后仍须重新输入冲刺 |

例如疲劳 70 时，普通步行每真实秒恢复 0.765，等待每游戏秒恢复 2.125；冲刺仍消耗 6。疲劳 80 以上时，两种恢复分别为 0.675 和 1.875，冲刺仍消耗 6。一次等待跨过疲劳阈值时继续分段积分，不能用起点倍率代替整段实际恢复。

精力倍率只是完整移动公式的一项。基础速度 0.86、疲劳速度影响、负重、专注、最后阶段和轮子倍率仍按已有规则组合。`characterMovementFactor` 同时供实际移动、共用行程估价与 HUD 的“当前步行速度”读取；HUD 不再将基础 0.86 误写成当前速度。恢复提示读取同一疲劳倍率，在 60／80 阈值显示实际降幅；冲刺时显示耗能，硬拖轮子时显示持续耗能。

轮子修理仍收费 20 游戏秒；硬拖仍使实际移动速度乘 0.9，并在移动时每真实秒额外消耗 1 精力。该扣耗不受疲劳倍率折减；普通步行恢复最多 0.9，低于轮子额外消耗。有储备时由储备填补缺口，储备用尽后当前精力随移动降低，最低为 0。停步、读题和固定等待不扣轮子费用，也不消费储备。修理、准备储备和休息仍根据当前状态及剩余路程体现用途。

本次针对性验证比较同一通道、同一实际用时下的纯走与短冲后步行，以及低／高疲劳下的节奏冲刺实际位移；同时检查疲劳只影响恢复、多轮耗尽和恢复、储备守恒、轮子额外消耗及 HUD 实际值。它们验证行为和边界，不预设通关率；最终误车率仍须用真实预算和明确操作策略另行评估。

## 4. 游客轮子：收益进入后续移动

游客上海／广州站内的 `tourist-wheel` 是处理障碍和持续耗能的取舍：

| 稳定选项 ID | 固定成本 | 本局后续效果 |
| --- | --- | --- |
| `repair` | 20 秒 | `wheelDamaged=false`，正常移动，不再承担轮子额外消耗；不降低行李负重，不附带隐藏精力扣除 |
| `drag` | 0 秒 | `wheelDamaged=true`；实际站内移动速度乘 0.9，实际移动每 1 真实秒额外消耗 1 精力，直到本局结束 |

`characterMovementFactor` 读取轮子状态，所以实际移动与共用该公式的行程预测一起反映减速。`tickCharacterResources` 在普通步行和冲刺时加入额外消耗；读题、暂停和阻挡时不扣这份费用，不因选择硬拖额外立即扣精力或加疲劳。界面持续显示速度与耗能原因。精力储备可以承担这份实际消耗，但不能抵消轮子带来的速度倍率。

剩余路程长、精力紧张时修理更有用途；时间很紧、剩余路程较短时可以选择硬拖。这是可比较的持续成本，不把 20 秒修理写成必定净省时间。事件关闭后的重复提交不会再收费或奖励。

## 5. 换层及家长资源统一封顶

| 任务／稳定选项 ID | 固定时间与标称资源效果 | 实际边界与消费者 |
| --- | --- | --- |
| 家长广州 `gz-lift` / `lift` | 45 秒；家长精力最多 +25 | 按家长自身上限恢复，影响后续速度和冲刺资格；满值显示实际 +0，可继续选作换层路线 |
| 家长广州 `gz-lift` / `stairs` | 12 秒；家长精力最多 −22 | 最低为 0，耗尽立即禁止冲刺；这项消耗不重复施加给孩子 |
| 家长 `parent-tired` / `rest` | 30 秒；家长精力最多 +7，孩子体力最多 +36，耐心最多 +8 | 每项分别按自己的上限显示，休息后使用恢复后的移动／阻挡状态 |
| 家长 `parent-patience` / `rest` | 25 秒；家长精力最多 +5，耐心最多 +32 | 耐心恢复为增量，不把已有较高耐心重置为更低值；精力封顶自身容量 |
| 家长杭州 `hz-parent-lift` / `right` | 18 秒；家长精力和孩子体力分别最多 +5 | 家长封顶自身容量，孩子封顶 100；左侧维修电梯仍是可见信息下的错误判断 |
| 打工人／游客 `gz-lift` / `lift`、`stairs` | 45 秒恢复最多 25／12 秒消耗最多 22 精力 | 各自封顶 60／35，显示当前实际增量 |
| 打工人／游客 `vertical-choice` / `lift`、`stairs` | 电梯 35 秒恢复最多 15／楼梯选择固定 0 秒、消耗最多 22 精力 | 后续换层操作另按实际时间完成，不重复收取同份资源费用 |
| 打工人郑州 `zz-hometown-answer` / `low-salary` | 固定 0 秒；专注最多 −5、精力最多 +5 | 按现有精力上限恢复，满值为 +0；不再为兑现 +5 临时扩容。`truth` 仍最多减 10 专注 |

家长其余自身精力扣耗和恢复也走 `applyParentChoice` 的统一封顶，包含抱起、安慰休息和六站任务。孩子体力、耐心与库存有各自语义：`parent-patience` 零食／安慰／休息分别最多恢复耐心 42／26／32；`parent-tired` 慢牵只补到至少 18，不压低已恢复的孩子体力。零食和水只有库存足够时提供消费选项，用完仍可安慰、购买或选择其他已有解法。

打工人、游客和家长选择楼梯或电梯后，完成对应换层操作就继续下一路段，不再误入一次扶梯操作。

家长卡片通过 `refreshParentPrompt` 调用同一效果函数预览实际资源差；通用换层、杭州电梯、饮水、周黑鸭、抱娃和孩子状态阻挡均按当前值刷新。饮水提示的额外尿意与时间自然增长分开说明。尿意仍遵循[孩子游戏时间结算规则 V1](./孩子游戏时间结算规则_V1.md)：固定等待推进生理时间一次，厕所完成后的归零在最后生效，不额外模拟一遍走路、冲刺或精力恢复。

## 6. 动态提示、稳定 ID 与真实记录

准备详情由当前人物状态生成；站内资源事件通过 `withResourceFeedback`、`refreshCharacterPrompt`、`refreshParentPrompt` 刷新。进入事件、读题中状态变化和提交选择时都读取当前实际边界，刷新不会更换正在处理的事件或重置操作进度。大学生的电梯、楼梯完成、岔气恢复以及广州换层同样展示当前可兑现的体力变化。

本轮改动的打工人／游客资源选项以及家长资源任务优先按稳定选项 ID 结算，旧标签保留兼容；修改展示文案不应改变效果。准备阶段通过步骤匹配防止重复购买，事件提交使用当前卡片的标准时间与选项，不信任传入的旧价格；失效事件和已完成选项不能再次收费或恢复。

准备和主动任务新增日志的 `resources` 保存实际发生的资源前值／后值，包括当前精力、容量、储备、疲劳、负重、专注和家长相关资源，而不是标称奖励。自然恢复的逐帧变化不伪装成任务奖励。储备真实消耗单独累计，结算数据读取 `energyReserveUsed`、剩余储备、轮子状态、留饭和实际来电次数；未使用库存不推断为固定时间收益，资源变化不与时间账本相加。

结算页展示储备已用／剩余和实际来电次数。零变化只有在当前资源达到上限时才标为“已满”，体力耗尽或已超过任务恢复目标不误报为满值。

## 7. 历史验证与范围（准备费用调整前）

本节保留 2026-10-11 资源修复验收时的证据。该批审计使用大学生旧准备费用 120／30／60 秒，全部选择共 210 秒；下述成功数和待修范围均属于当时版本，不能作为本页第 8 节费用调整后的验收或通关率。

针对性回归覆盖空值、普通值、接近上限和满值，学生准备组合、奶茶在进站前后的窗口、饭团饱腹、储备真实消费与耗尽阈值、轮子实际速度与耗能、家长恢复和楼梯消耗、库存耗尽、选项重复提交、动态卡片与实际日志。大步延迟和相同小步序列比较资源、移动和剩余时间，继续保留此前统一计时、冲刺、尿意及路线公式回归。界面验证包括组件渲染出的实际收益、可选项和状态反馈；这些验证不等于浏览器手动试玩。

本轮真实预算审计为 4 人物 × 6 车站 × 2 难度 × 3 固定策略，共 144 局，全部到达结算：90 局成功、54 局因截止时间失败，无卡死。共检查 175,991 次状态转换，包含 277 个事件快照选项分支探针及额外恢复边界探针，检查到的资源均在各自范围内；家长休息曾越界的案例现在为 70/70。

审计保留游戏生成的真实初始预算，不追加剩余时间；准备和普通选择读题通常计 2 秒，按住按配置计时，连点按每次 0.2 秒，使用正确证件／编号并避让路障。三套策略覆盖不同准备、路线、补觉和换层选择，站内以步行为主。证据为仓库外的 `/workspace/scratch/resource-audit.ts` 与 `/workspace/scratch/resource-audit-results.txt`。90/144 是这些固定策略和种子的模拟结果，不是真人通关率，不证明所有策略都应成功；277 个分支也不是 277 局完整流程或浏览器交互。

本轮没有宣称原审查全部完成。扶梯额外加速文案、检票通道显示的附加步行成本、各类固定等待对疲劳和耐心的统一活动规则、静态路线最优标签，以及其他独立交互问题仍按原审查另行处理。未接入标准入口的旧事件、游客导航死分支和未开放家庭角色不因本轮动态资源提示而视为已上线或验收通过。

后续修订：等待、乘车及操作的活动结算以[等待状态与操作规则 V1](./等待状态与操作规则_V1.md)为准，特别是上文“固定等待不推进自然恢复”的概括现已细化为实际等待推进被动资源、任务定额替代同字段、步行和操作不冒充休息；本页历史正文保留。

## 8. 大学生准备费用修订（本轮难度校准）

本轮降低准备之间的固定时间差，让资源、证件信息和后续操作继续决定准备的用途。六站、普通与极限两种模式共用奶茶 45 秒、查身份证 10 秒、饭团 25 秒；全选为 80 秒，检查证件加饭团为 35 秒，跳过对应准备为 0 秒。原先的 120／30／60 秒及 210 秒合计不再是当前价格。第 2 节的容量上限、实际增量、饱腹、持杯影响与进站恢复窗口继续适用。

费用的唯一来源是 `src/studentConfig.ts` 的 `STUDENT_PREPARATION_COSTS`；`STUDENT_PREPARATION_TOTAL` 从三项费用求和，不另写一个 80。后续修改准备时必须同时检查以下消费者：

| 消费者 | 当前约定 |
| --- | --- |
| 准备卡片与 `PREP_PICK` | 展示和结算读取同一选项费用；固定成本扣一次，读题与输入的实际经过时间照常流逝，重复提交不再次收费或加属性 |
| 准备日志、`TimeImpact`、`decisionLoss` | 保存实际选择的 45／10／25 秒；不能继续记录旧价格，也不能把获得资源折算成保证追回的秒数 |
| 结算 `extraPreparationSeconds` 与学生报告 | 按实际准备费用汇总；报告中的检查耗时、奶茶花费和跳过奶茶保留的固定时间都读同源常量 |
| `student_tea_loss`／`student_food_loss` 称号 | 仍需对应准备为决定性负向因素，失败缺口不超过该项实际费用 45／25 秒；组合准备产生的更大缺口不能全归因于一项 |
| `student_management` 与 `optional_delay` 称号 | 学生准备门槛读取三项总费 80 秒；时间管理称号另保留成功余量小于 120 秒的独立窗口。其他人物的准备耗时门槛保持原规则 |
| `secret-student` 成就 | 保留稳定 ID，准备门槛与说明均读取总费 80 秒，同时继续要求成功、余量不超过 10 秒及至少一次错误；不重置既有存档中已解锁的成就 |

本轮针对性回归覆盖实际准备支出与资源边界、组合顺序、学生流程、真实日志和结算指标、报告文案、称号败因边界及降价后称号／成就可达性。费用调整不增加资源上限、不补回当前体力缺口、不暗中返还时间；预算和成功率需按[预算、实际耗时与预测规则 V1](./预算实际耗时与预测规则_V1.md)另行校准与验收，本节不发布最终成功率。

原始人物、事件和结算设计稿中奶茶“两分钟”、准备 120／30／60 秒、按旧准备费用举例的称号及归因案例保留为历史设计，由本节覆盖其现行准备价格和消费者要求。第 7 节及审查文档的旧验收数量也保留原值。打工人吃饭 60 秒、游客短休 30 秒、任务等待 60 秒、称号独立余量 120 秒等各自有明确含义，不能随学生准备费用一起替换。
