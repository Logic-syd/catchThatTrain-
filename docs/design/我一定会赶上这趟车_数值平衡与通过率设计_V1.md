# 《我一定会赶上这趟车》数值平衡与通过率设计方案

版本：V1  
用途：供产品设计、数值校准、Codex 开发与自动化测试  
目标：让五类人物都存在稳定可通关解，同时形成清晰的难度梯度；大学生“只要别错太多就能过”，后续角色逐渐降低通过率。

---

# 1. 总体目标

游戏的数值设计需要同时满足四件事：

1. 每个角色都能稳定通关
2. 不同角色的难度明显递增
3. 失败主要来自玩家决策和操作，而不是纯随机
4. 玩家熟练后能明显提高成功率

推荐普通玩家目标通过率：

| 角色 | 目标通过率 |
|---|---:|
| 大学生 | 80–90% |
| 打工人 | 65–75% |
| 疲惫游客 | 55–65% |
| 带娃家长 | 45–55% |
| 出行家庭 | 35–45% |

熟练玩家应明显高于此区间。

---

# 2. 难度设计的核心：容错预算

不要通过简单缩短所有角色的倒计时制造难度。

真正控制难度的变量应该是：

> 角色可以犯多少错。

定义：

```ts
errorBudget
```

即：

> 在标准完成路径之外，玩家最多还能额外浪费多少时间。

推荐第一版：

| 角色 | 容错预算 |
|---|---:|
| 大学生 | 240 秒 |
| 打工人 | 180 秒 |
| 疲惫游客 | 135 秒 |
| 带娃家长 | 90 秒 |
| 出行家庭 | 60 秒 |

这样会形成自然梯度。

---

# 3. 大学生的设计目标

大学生是最低难度人物。

他的设计体验应该是：

> “只要别连续犯大错，大概率能赶上。”

240 秒容错意味着：

例如一局发生：

```text
买奶茶             -120 秒
走错一次             -55 秒
安检判断不够好         -30 秒
----------------------------
总损失               -205 秒
```

仍有约 35 秒余量。

但如果再多犯一个明显错误：

```text
身份证翻包            -45 秒
```

就可能失败。

因此大学生既不会轻松到无脑过关，也不会因为一次小失误直接死局。

---

# 4. 统一初始时间公式

目前不同角色如果分别写：

```ts
bestRoute + 240
bestRoute + 480
fixed 35:30
```

会导致角色难度失控。

所有人物都应该使用同一套公式：

```ts
initialVisibleTime =
  bestMetroReferenceTime
  + stationReferenceTime
  + mandatoryInteractionTime
  + expectedEnvironmentLoss
  + characterErrorBudget
  + stationBalanceOffset
```

如果游戏内部还保留“停止检票前 180 秒”：

```ts
run.initial =
  initialVisibleTime
  + STOP_BEFORE
```

即：

```ts
STOP_BEFORE = 180
```

统一之后，角色之间只通过：

- 标准移动能力
- 人物机制
- 容错预算

产生差异。

---

# 5. “时间多”不等于“角色简单”

移动慢的角色可以拥有更长的初始倒计时。

例如：

```text
大学生
总倒计时：30:30
标准完成：26:30
真正容错：4:00

游客
总倒计时：33:00
标准完成：30:45
真正容错：2:15
```

游客虽然看起来多了 2 分半钟，但他真正能浪费的时间反而更少。

因此角色难度应该看：

```text
容错 = 初始倒计时 - 标准完成时间
```

不要单独比较倒计时长度。

---

# 6. 标准完成时间必须使用“参考玩家”

不能用：

- 完全不跑
- 全程冲刺

作为基础标准。

建议定义一个：

```ts
referencePlayer
```

这个玩家会：

- 基本选正确路线
- 正常看提示
- 偶尔冲刺
- 有正常反应时间
- 不追求极限操作

---

# 7. 参考冲刺比例

标准耗时计算时，默认玩家会适度跑动。

建议：

| 角色 | referenceSprintDuty |
|---|---:|
| 大学生 | 15% |
| 打工人 | 10% |
| 疲惫游客 | 6% |
| 带娃家长 | 8% |
| 出行家庭 | 4% |

计算思路：

```ts
referencePace =
  walkFactor *
  (1 + sprintDuty * (sprintMultiplier - 1))

stationReferenceTime =
  stationDistance / referencePace
```

这样：

- 完全不跑：会消耗一部分容错
- 合理分段冲刺：接近标准值
- 操作优秀：能额外节约几十秒
- 全程乱冲：由于体力和机制惩罚反而可能失败

---

# 8. 冲刺系统不能用“巨大断崖罚时”

当前玩法理念应保留：

> 一直无脑冲刺会失败。

但不建议一次岔气直接损失 100 秒以上。

这种惩罚过于跳跃，会让低难度角色也显得不公平。

建议大学生：

```ts
breathLimit = 7s
```

第一次连续乱冲导致岔气：

```text
罚时 35 秒
```

第二次：

```text
罚时 45 秒
```

第三次：

```text
罚时 60 秒
```

同时加入短暂：

- 强制停步
- 恢复体力
- 冲刺效率下降

这样全程乱冲仍会失败，但偶尔操作失误不会直接毁掉一局。

---

# 9. 玩家失误分级

建议所有失误统一分为三档。

## 小失误

约：

```text
10–30 秒
```

例如：

- 没提前靠门
- 决策慢
- 翻错一次包
- 小绕路
- 临时停顿

## 中型失误

约：

```text
30–75 秒
```

例如：

- 选错安检队
- 走错一个区域
- 电梯判断错误
- 找错出口
- 孩子临时事件处理不佳

## 大失误

约：

```text
75–150 秒
```

例如：

- 坐过站
- 坐反方向
- 严重路线错误
- 多次连续岔气
- 家庭无障碍路线彻底选错

---

# 10. 五个角色应能承受的失误量

## 大学生

目标：

```text
2–3 个小失误
+
1–2 个中型失误
```

仍有机会通关。

一次大失误后仍可能靠优秀操作救回来。

## 打工人

目标：

```text
1–2 个小失误
+
1 个中型失误
```

比较安全。

再错一次就开始压线。

## 游客

目标：

```text
1 个中型失误
+
少量小失误
```

已经很紧。

## 带娃家长

目标：

```text
1 个明显错误
```

就会进入高压状态。

但不能因为一个随机孩子事件直接必输。

## 家庭

目标：

```text
路线和分工大部分都要正确
```

允许少量小错误。

核心困难来自系统复杂度，不应依赖极端数值惩罚。

---

# 11. 环境随机事件单独控制

纯随机负面事件不能吃掉大部分角色容错。

建议：

```ts
EXPECTED_ENVIRONMENT_LOSS = 35
MAX_ENVIRONMENT_LOSS = 75
```

含义：

正常一局预计有：

```text
约 35 秒不可控环境损失
```

最倒霉的一局：

```text
最多约 75 秒
```

达到预算后：

- 纯负面随机事件概率显著下降
- 后续更偏向可操作事件
- 避免 RNG 连续判玩家死刑

---

# 12. 什么算环境损失

计入环境预算：

- 地铁临停
- 临时施工
- 电梯突然满员
- 扶梯临时故障
- 检票口临时调整
- 不可预见的人流阻塞

不计入环境预算：

- 玩家选错队
- 玩家走错方向
- 玩家不看地图
- 买奶茶
- 回工作消息
- 不提前处理孩子尿意
- 选择错误电梯
- 连续冲刺岔气

这些属于：

```text
player-caused loss
```

---

# 13. 地图差异不要主要靠通过率

六张地图第一阶段不建议做成：

```text
杭州很简单
广州特别难
```

人物难度应该大于地图难度。

地图的核心区别应该体现在：

> 失败原因不同。

## 上海虹桥
主要考：
- 体力
- 长距离
- 冲刺分配

## 北京南
主要考：
- 安检队判断
- FOCUS

## 广州南
主要考：
- 综合路线
- 人流
- 换层

## 杭州东
主要考：
- 导视
- 方向判断

## 武汉站
主要考：
- 楼层规划
- 楼梯 / 扶梯 / 电梯

## 郑州东
主要考：
- 编号识别
- 对称区域导航

---

# 14. 地图平衡偏移量

如果自动测试发现地图天然有偏差，可以加入：

```ts
stationBalanceOffset
```

建议限制：

```text
-30 秒 ～ +30 秒
```

例如：

```ts
guangzhou: -15
hangzhou: +15
```

不要用几分钟级修正。

否则地图数值会盖过人物数值。

# 16. 人物移动公式必须统一

所有角色的移动逻辑都应该基于统一模型。

建议：

```ts
movementFactor =
  baseSpeed
  * energyFactor
  * fatigueFactor
  * loadFactor
  * specialStateFactor
  * sprintFactor
```

其中：

```ts
sprintFactor =
  sprinting
    ? character.sprintSpeed
    : 1
```

不要再出现角色配置写：

```ts
worker.sprintSpeed = 1.65
```

实际计算却统一使用：

```ts
1.55
```

角色配置必须真正参与数值计算。

---

# 17. 标准移动能力应从人物配置读取

推荐统一角色 profile：

```ts
interface CharacterBalanceProfile {
  id: CharacterId

  baseSpeed: number
  sprintSpeed: number

  maxEnergy: number
  sprintDrain: number
  walkRecovery: number
  restRecovery: number

  load: number
  focus: number
  fatigue?: number

  referenceSprintDuty: number
  errorBudget: number
}
```

这样所有角色平衡集中管理。

---

# 18. 游客睡觉的时间模型

游客“地铁睡觉”不应该额外创造旅行时间。

如果地铁本来就需要：

```text
8 分钟
```

玩家选择睡：

```text
45 秒
```

这 45 秒应该属于已经存在的地铁行程。

正确逻辑：

```text
地铁继续行驶
+
游客恢复 EN
+
FATIGUE 下降
+
增加睡过站风险
```

不应该：

```text
地铁暂停
+
再额外扣 45 秒
```

否则游客会被重复计算时间。

---

# 19. 家庭和带娃角色也要遵守同一模型

带娃家长：

标准耗时要包含：

- 孩子正常移动速度
- 少量正常等待
- 基础牵手影响

不能把所有孩子事件提前算进标准耗时。

孩子真正闹情绪、尿急等属于：

```text
run variance
```

家庭：

标准耗时要包含：

- 婴儿车基础速度
- 合理的无障碍路线
- 正常分工

不应该假设：

- 电梯永远故障
- 孩子一定哭
- 一定忘东西

这些属于局内事件。

---

# 20. 通过率不能靠人工体感校准

需要做自动化模拟。

建议建立：

```ts
balanceSimulation.test.ts
```

每个组合运行：

```text
6 个地图
×
5 个角色
×
1000 个 seed
```

总计：

```text
30,000 局
```

# 21. 三类模拟玩家

## 熟练玩家 Bot

行为：

- 总选合理路线
- 看提示
- 合理分段冲刺
- 正确管理角色机制
- 反应约 2–3 秒

目标：

| 角色 | 熟练通过率 |
|---|---:|
| 大学生 | ≥95% |
| 打工人 | 85–90% |
| 游客 | 75–85% |
| 带娃家长 | 65–75% |
| 家庭 | 55–65% |

## 普通玩家 Bot

行为：

- 大部分决策正确
- 偶尔选错
- 反应约 4–6 秒
- 不会完美管理体力
- 会做角色剧情选择

目标：

| 角色 | 普通通过率 |
|---|---:|
| 大学生 | 80–90% |
| 打工人 | 65–75% |
| 游客 | 55–65% |
| 带娃家长 | 45–55% |
| 家庭 | 35–45% |

## 乱玩玩家 Bot

行为：

- 经常不看提示
- 冲刺管理差
- 随机选路线
- 反应慢
- 会连续犯错

通过率应该明显低。

但游戏仍需要输出：

- 合理失败原因
- 正确称号
- 可理解复盘

# 22. 必须增加 Clean Bot

还需要一个：

```ts
CleanBot
```

行为：

- 永远做理论正确选择
- 合理冲刺
- 无操作错误

验收：

```text
6 地图 × 5 角色 × 大量 seed
```

都必须：

```text
100% 存在稳定通关路径
```

用途：

避免出现：

> 某个 seed 从开局开始就数学上无解。

---

# 23. 调参顺序

平衡时不要同时改所有参数。

建议固定顺序：

### 第一层
统一初始时间公式

### 第二层
修正角色移动速度

### 第三层
设置 errorBudget

### 第四层
校准环境随机预算

### 第五层
校准事件时间成本

### 第六层
最后才做地图 ±30 秒修正

这样才能知道每次调整到底影响了什么。

---

# 24. 数值调优原则

当某角色通过率太低：

优先检查：

1. 标准完成时间是否算错
2. 是否存在重复扣时
3. 某事件是否惩罚过大
4. 随机事件是否连续出现
5. reference player 是否假设过于理想

最后才增加容错预算。

当某角色通过率太高：

优先检查：

1. 标准耗时是否低估
2. 冲刺收益是否过高
3. 错误事件是否没有实际成本
4. 是否存在大量“免费恢复”
5. 某人物 Buff 是否叠加过强

最后才减少容错预算。

---

# 25. 最终设计目标

大学生：

> 错一点没关系，连续作死才会错过。

打工人：

> 做对判断比一直跑更重要。

游客：

> 管不好疲劳，很快就会失去容错。

带娃家长：

> 自己跑得动，孩子的需求会不断吃掉余量。

家庭：

> 每一步都要计划，稳定完成才有较高成功率。

最终希望形成的体验是：

```text
角色越往后
↓
玩家可以犯的错误越少
↓
系统复杂度越高
↓
但始终存在公平、稳定、可学习的通关方式
```

游戏难度应该来自：

**决策压力 + 资源管理 + 操作熟练度**

而不是：

**系统随便多扣几分钟。**
