## 1. 现在实际生效的规则

**用正常完成之后还能耽搁多少时间来区分人物难度。** 普通模式采用：

```text
开局可见时间 = 向上取整到 1 秒（
  正常地铁行程 + 站内赶路 + 必要操作 + 预计环境耽搁 + 人物容错
）
```

| 人物 | 正常参考耗时以外的容错 |
| --- | ---: |
| 大学生 | 240 秒 |
| 打工人 | 180 秒 |
| 疲惫游客 | 135 秒 |
| 带娃家长 | 90 秒 |

前四项取自上一轮 [正常完成参考耗时 V1](./我一定会赶上这趟车_正常完成参考耗时_V1.md) 的 24 组完整测量，基线报告提交 `3ae6fd3`，引擎基线 `9d6a228`。轻量配置保存在 `src/referenceBudgets.ts`，不用在浏览器加载整份测量报告。

环境项使用该人物、该站的**观测平均额外处理成本**，没有再叠加计划中的 35 秒。35 秒均值、75 秒上限的统一环境规则仍是后续工作。本次也没有把旧 buffer、人物站点补偿或检票后路程叠加进新预算。

同一环境种子下，正常耗时会偏离均值；所以实际完成余量会围绕人物容错波动，不是每局保证正好剩 240 秒。体力、负重、剧情取舍和选路仍会改变真实耗时。改选准备、选路更好或犯错，都是在同一固定开局预算内产生不同结果，不会动态给玩家补偿时间。

只向上取整到 1 秒，额外余量小于 1 秒。内部发车时钟仍为可见检票倒计时加 180 秒，检票后的登车用时仍单独结算。

## 2. 撤掉角色统一罚时倍率

已移除 `navigationMistakeMultiplier` 及其调用。原来同一方向错误按大学生／打工人／游客／家长乘 1／1.2／1.4／1.6；现在直接使用事件本身的成本。

例如杭州东误入西侧到达出口，四个人物都扣 **45 秒**。它占大学生 240 秒容错的 18.75%，占家长 90 秒容错的 50%。同一个错误更伤家长，原因是犯错余量更少。

六站自己的剧情、路线分支、行走距离、安检速度、操作和角色专属事件保持原值。没有把各站改成同一套任务，也没有抹平负重、疲劳、带娃等机制产生的真实差异。

## 4. 验证结果

### 实际倒计时下的参考流程

4 人物 × 6 站 × 32 种子，共 768 局，使用与上一轮相同的准备、5 秒读题和人物参考冲刺节奏。**测量延长量为 0**，全部在真实新倒计时内通过检票并登车。

| 人物 | 各站平均检票余量范围 | 全部受测种子最小检票余量 |
| --- | ---: | ---: |
| 大学生 | 240.48–240.93 秒 | 207.75 秒 |
| 打工人 | 180.26–180.94 秒 | 146.48 秒 |
| 疲惫游客 | 135.12–135.67 秒 | 101.07 秒 |
| 带娃家长 | 90.07–90.88 秒 | 46.35 秒 |

这验证了“参考基线＋指定容错”确实接入，**不代表真人首次通过率为 100%**。玩家操作、准备和迷路方式仍需后续试玩校准。

### 账本与规则回归

- 720 组普通／极限、不同准备、步行／分段冲刺／持续冲刺／方向失误场景，实际倒计时与账本误差为 0，无未分类扣时、无未完成脚本。
- 所有 48 组普通／极限开局，都能用五项预算、取整与极限减时复算；发车与检票截止仍相差 180 秒。
- 同一方向误判经实际选择后，四人物扣时一致；地铁报站原有固定成本保持原值。
- 对四个人物扣除各自固定参考成本，再逐次加入完全相同的 60 秒损失，分别在第 5／4／3／2 次耗尽余量。按秒取整留下的小于 1 秒余量会影响恰好卡线的结果；这只是受控预算验证，不代表任何玩家每局必能错这么多次。
- 排队、睡眠、安检和检票后的原有防重复记账测试继续通过。

[参考流程报告](./mistake-budget-report.json)保留 768 局实际剩余时间；[扣时对账报告](./mistake-budget-time-audit.json)保留 720 组场景。历史报告不覆盖。

## 5. 明确保留到下一步的问题

用户本轮确认：**先验证新容错，冲刺下一步调。** 因新增容错，一个几乎不读题、跳过所有准备、持续冲刺的北京脚本可以过关；原先“无脑冲必败”的绝对断言已不适用于这组预算。

本次不提高岔气罚时，不缩小容错来掩盖该现象。持续冲刺仍反复触发原有 105 秒岔气成本，后续单独调整持续冲刺的收益与代价。测试保留连续岔气、停步恢复、正常步行和分段冲刺可完成的检查；不再把所有持续冲刺局必败作为本轮验收条件。

新手、熟练玩家的目标通过率、环境损失上限、多种准备取舍的可玩性仍待后续验证。站点基线是已声明参考策略的快照；以后改地图、正常排队、移动能力或操作时长时，需要重新测量更新它，不能长期沿用过期数据。
