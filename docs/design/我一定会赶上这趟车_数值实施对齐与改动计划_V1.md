## 1. 要达成的体验

玩家急着赶车，沿地图移动，被人群、设施和自身状态打断；通过观察、操作和资源分配争取赶上。人物逐级增加管理难度，并减少犯错余量。玩家熟悉规则后，应能明显提高成功率。

本轮沿用已有设计约定：

- 每局从随机出现的两个车站中选一个；六站具有各自地图、路线与典型阻碍。
- 大学生起步，通关后依次解锁打工人、疲惫游客、带娃家长；出行家庭仍是规划人物。
- 地图赶路、固定底部大操作区、小人的动作反馈和实际扣时提示继续保留。
- 完整通关至少 12 次有效操作；一次完整按住、滑动或连点任务只计一次，等待和重复输入不计数。提前失败的局不要求凑满 12 次。
- 选项初始同色，普通选项顺序不能永远暗示答案；保留可观察线索与有吸引力的误判选项。
- 明确成本、资源取舍可展示；隐藏随机概率与尚未发生的结果。选择后说明实际后果。
- 大学生准备仍是小蛋糕：带上耗时 75 秒、专注 +5、负重 +5、占手并增加赶路消耗；不带专注 −5。原稿奶茶例子用于说明预算，不恢复旧奶茶事件。
- 没听清报站：去门口扣 5 秒和 5 体力；继续坐扣 5 秒，可能坐过站另扣 50 秒。此次不擅自修改这组已约定成本。

## 2. 统一难度目标

| 人物 | 额外容错预算 | 参考冲刺比例 | 普通玩家目标通过率 | 熟练 Bot 目标 |
| --- | ---: | ---: | ---: | ---: |
| 大学生 | 240 秒 | 15% | 80–90% | ≥95% |
| 打工人 | 180 秒 | 10% | 65–75% | 85–90% |
| 疲惫游客 | 135 秒 | 6% | 55–65% | 75–85% |
| 带娃家长 | 90 秒 | 8% | 45–55% | 65–75% |
| 出行家庭（规划） | 60 秒 | 4% | 35–45% | 55–65% |

这是新的校准目标，大学生目标取代之前约 75% 的讨论口径。表内数值是待验证参数，不能写成已经达到的结果。参考冲刺比例按站内实际移动时间计算，排队、读题、休息不进入分母。

通过率须按人物、站点、普通/极限模式、首次/重玩分别记录。真人首玩应使用该玩家首次挑战该人物的样本；重复尝试、主动中退和技术中断单独列出，不能静默混合或删去。原稿称“普通玩家”，具体真人统计暂采用这一口径，后续试玩表也应标明。

熟练 Bot 仍有有限反应时间、偶发判断或资源管理偏差；CleanBot 用来验证不犯操作错误且合理管理资源时的可通关性。不能为了卡住熟练 Bot 的目标上限，给游戏额外加入必败随机数。

## 3. 标准耗时、容错和途中判死分别计算

### 3.1 初始时间

```text
可见初始倒计时（距离停止检票） =
  参考地铁行程
  + 参考站内移动
  + 必要交互时间
  + 预计不可控环境损失
  + 人物容错预算
  + 站点校准偏移

内部 run.initial = 可见初始倒计时 + STOP_BEFORE
STOP_BEFORE = 180 秒
```

计时分项使用不重叠的归属：

| 分项 | 包含 | 不重复包含 |
| --- | --- | --- |
| 地铁行程 | 乘车、正常换乘步行 | 因坐错方向或坐过站产生的折返 |
| 站内移动 | 角色基础能力下的正常赶路、参考分段冲刺与合理路线 | 排队、读题、事件固定扣时 |
| 必要交互 | 必须经历的正常排队、读题反应、选路、安检操作、刷证等 | 已计入其他分项的行程与等待 |
| 预计环境损失 | 基准预计的额外不可控耽搁 | 正常安检本身、玩家选错队后多等的时间 |
| 容错 | 超出参考完成路径的额外耗时余量 | 必做任务的正常完成耗时 |

至少 12 次有效操作的合理读题和动作时间必须进入参考流程。地图上的同一次放包或刷证不能同时作为两个独立必做耗时。通过检票后的登车另受发车时刻约束，不能把登车路程重复算入检票截止前的标准耗时。

参考准备组合需要显式记录：哪些准备计入基线、哪些是可选剧情成本，以及它们造成的负重、体力上限、专注和后续事件变化。不能把带蛋糕、陪妈妈等有价值的取舍统称为“操作错误”，也不能只扣时间而忽略收益。

原稿的六站倒计时表作为对照，不硬编码覆盖计算结果。若公式与表格差很多，先查路径、单位、能力或重复扣时。

### 3.2 参考玩家

参考玩家基本认路、正常看提示、有反应时间、适度分段冲刺。当前脚本的“冲 4 秒、走 3 秒”和知道所有选项耗时的选择方式，不能直接当作这份原稿的参考玩家。

解析公式可作为初估：

```text
参考速度 ≈ 步行速度 × [1 + 冲刺占比 × (冲刺倍率 − 1)]
```

最终用实际引擎复核精力、疲劳、负重、停步恢复和角色机制随时间的变化。短按连续输入、一次性长时间推进和正常逐帧推进，必须得到一致的账本结果。

### 3.3 途中时间比较

参考耗时用于分配开局时间；途中“理论最短”用于保守预警，两者不得混用。

- 少于正常参考耗时：局势紧张，仍可能通过更好的操作挽回。
- 少于严格乐观的剩余时间下限：才显示“这趟肯定赶不上了”。
- 检票前比较停止检票时间；检票后比较发车时间。
- 提醒本身不额外扣时，不自动终止游戏，也不泄露哪条选项是正确答案。

当前下限计算允许极限速度、免费恢复并忽略未来阻挡，属于偏保守的判死条件，不是承诺玩家真能以该用时到达。统一移动模型后应同步更新此计算；如果暂时不能证明某一项是不可避免耗时，就先不把它加入必败判断。

## 4. 当前实现与计划修改

| 项目 | 当前实现（基线 96baa9c） | 计划修改 |
| --- | --- | --- |
| 开局预算 | 大学生、打工人/游客、家长分支各自计算，使用不同 buffer | 共用分项公式，保留可检查的预算明细 |
| 容错递减 | 方向错误按人物乘 1 / 1.2 / 1.4 / 1.6 | 完成标准耗时校准后撤掉统一角色罚时倍率，使用 240 / 180 / 135 / 90 秒容错 |
| 角色速度 | 大学生、打工人/游客、家长使用不同函数与字段语义 | 集中角色配置并统一组成项，角色特殊状态仍保留 |
| 岔气 | 连续冲刺 7 秒触发，一次固定扣 105 秒 | 前三次改为 35 / 45 / 60 秒，并校准强制恢复与重复乱冲的效率损失 |
| 环境损失 | 部分规则有局部限制，尚无全角色统一的 35 / 75 秒预算 | 分离正常过程、不可控额外损失和玩家造成的额外损失 |
| 游客睡觉 | 已按地铁进度跳到叫醒站，睡眠选项固定成本为 0；恢复量按所选提前站数给定 | 保留不重复扣车程，校验提前换乘等截短睡眠时的实际恢复量 |
| 站点校准 | 分站 buffer 与人物例外补偿存在 | 先排查结构成本，最后才使用独立的 ±30 秒偏移 |
| 自动模拟 | 已有固定策略、不同读题时间和错误次数的模拟 | 加入 Clean、熟练、普通、乱玩四套行为模型，统一随机种子与统计口径 |
| 家庭 | 尚无可玩的完整机制 | 预留配置，暂不声称完成五人物通过率校准 |

移除统一罚时倍率不表示所有人物的真实损失必须相同。拖箱子折返慢、抱娃绕路费力，可以由移动与负重产生；有明确剧情原因的专属处理成本仍独立定义。先定位原始时间账本，避免在真实慢速之上再加一次无原因的角色罚款。

速度字段先明确单位：现有打工人 `baseSpeed=0.9`、`sprintSpeed=1.65` 是计算中的两个速度基准。若迁移为“步行基准 × 冲刺倍率”，对应倍率约为 `1.65 / 0.9`；不能直接再乘 1.65，意外改变角色速度。

## 5. 事件成本与随机预算

事件按损失来源区分，并在结算保持同一口径：

| 来源 | 例子 | 处理原则 |
| --- | --- | --- |
| 正常必要过程 | 正常排队、放包、刷证 | 进入参考时间；真实经历仍照常扣时 |
| 主动资源或剧情取舍 | 带蛋糕、回复老板、陪妈妈 | 计算时间成本和全部即时/后续收益 |
| 可避免的判断或操作损失 | 认错方向、忽略维修牌、选错队、连续岔气 | 消耗玩家容错；小/中/大失误分别参考 10–30 / 30–75 / 75–150 秒 |
| 不可预见的环境额外损失 | 临停、突然故障、无法预见的封堵 | 平均目标 35 秒、单局上限 75 秒 |

环境上限约束实际不可控额外耗时，不能只限制出现次数。读题犹豫和自选绕路不算环境预算；可操作的人群事件中，无法避免的最低等待与玩家拖延也要分开。

初始预算已含预计环境损失 35 秒，因此环境实际达到 75 秒时，相对参考流程多消耗 40 秒容错。日志是对已扣时间的解释，不能再次减倒计时。

预算接近上限时，在触发新随机事件之前调整：缩短后续纯等待、减少纯负面抽取，或改成玩家能处理的阻挡。不能事件已经扣完时再偷偷返时间，也不能用“新可操作事件”名义继续塞入不可避免的超额罚时。

已知维修牌、不提前处理孩子尿意和明知的风险选择继续按原因归账。带娃角色的基础牵手速度进入标准耗时；真正的需求变化单独记录，避免假设孩子必定哭闹，再把所有坏结果提前补偿。

岔气第四次及之后的成本和效率下降细则属于待校准参数，不在本稿假装已确定。验收同时要求偶发一次乱冲有机会救回、持续无脑冲刺不能成为稳定通关策略；若只降低固定罚时导致全程乱冲占优，需修正冲刺收益与恢复机制。

## 6. 实施顺序与每步验收

| 步骤 | 具体工作 | 验收结果 |
| --- | --- | --- |
| 1. 统一时间账本和初始公式 | 列出地铁、移动、必要操作、环境、容错、站点偏移；先记录旧参数差异 | 所有人物实际扣时可对账；睡眠、队列、刷证不重复计算 |
| 2. 统一移动配置 | 明确速度与倍率语义，串起体力、疲劳、负重和特殊状态 | 同样操作的前后速度差异可解释；恢复不超过上限；配置实际参与计算 |
| 3. 校准参考玩家和容错 | 使用角色参考冲刺占比，固定准备基线；落实人物 errorBudget，替换统一折返倍率 | 正确标准路径稳定可过，额外失误耗尽对应余量 |
| 4. 校准环境预算 | 统一不可控损失分类、预期值和上限；覆盖最坏连续事件 | 最倒霉开局仍有合理操作的通关路径 |
| 5. 校准事件与冲刺 | 调整岔气阶梯、延迟效果、剧情取舍和恢复收益 | 两个选项在不同状态下均有选择价值；无脑冲刺失败有因可循 |
| 6. 最后微调地图 | 按各人物逐站检查，定位天然偏差，才用 ±30 秒偏移 | 地图主要改变难点，不盖过角色难度梯度 |

每步保留同一组种子的前后结果，避免同时调多个参数却无法解释变化。首轮先用大学生打通统一账本、参考节奏和岔气，再接入打工人、游客与家长；全部使用同一模型。测试版验收后再安排正式合并和版本标签。

## 7. 模拟和真人验证

### 模拟玩家

| 类型 | 行为定义 | 验证用途 |
| --- | --- | --- |
| CleanBot | 合理准备和路线、可持续冲刺、无操作失误，完成必要动作 | 全部受测种子通关，检查开局公平性 |
| 熟练 Bot | 理解线索、管理资源，约 2–3 秒反应，仍允许有限偏差 | 验证熟练度带来的收益 |
| 普通 Bot | 大部分决策正确，约 4–6 秒反应，准备与剧情选择多样，体力管理不完美 | 校准人物通过率区间 |
| 乱玩 Bot | 易受误导、连续犯错、冲刺管理差、反应较慢 | 验证低通过率与可理解的失败原因 |

熟练、普通、乱玩 Bot 不能读取内部 `optimal`、隐藏排队秒数或尚未揭晓的抽签结果。其行为概率属于测试模型，要固定、记录并用真人数据校正；不能调 Bot 失误频率来伪造游戏已平衡。

CleanBot 的可执行策略也应尊重玩家可见线索。若额外使用读取全局状态的最优路径搜索，报告应明确标为离线可解性检查；“存在某条路径”与“玩家能依据提示找到这条路径”分开验证。

### 数量和报告

- 先用少量固定种子做每次改动回归，再跑大样本；批量模拟独立执行，普通提交检查保留小样本。
- 当前四人物：6 站 × 4 人物 × 1,000 种子 = 每类 Bot 24,000 局；四类都跑共 96,000 局。
- 家庭实际完成后：每类 Bot 30,000 局，四类共 120,000 局。不能把只跑一种策略的 30,000 局当作所有行为的验证。
- 环境抽样、玩家行为和界面选项顺序采用可复现且分开的种子流；渲染、读地图、重算预警不能重新抽环境结果。
- 输出每组成功数/总数、成功余量与失败差距分布、失误构成、环境损失、冲刺与恢复、有效操作次数；失败保留种子及动作轨迹。
- 大样本的 CleanBot 全通过只说明受测集合通过，不能据此宣称数学证明所有可能开局都有解。发现无解种子应定位机制或时间缺口。
- 目标通过率先检查人物整体梯度，同时逐站观察偏差；真人数据按首次/重玩、人物与车站分组回看。保留地图间合理差异，不用大型补时强行抹平。

手机验证继续检查按钮是否始终够大且可见、操作切换是否明显、疲惫与扣时反馈是否清楚。脚本成功不能代替触控试玩，真人数据不足时明确标为待验证。
